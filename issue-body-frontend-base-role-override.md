An app that declares a route for a role always wins over the site's `externalRoutes` for that role, so a site cannot send a role an installed app declares to a destination of its own. Found while porting Learning's tab links to route roles (openedx/frontend-app-learning#1905): an operator who wants Learning's dates or outline link to go somewhere else has no way to say so.

## How a role resolves today

- [`getUrlByRouteRole`](https://github.com/openedx/frontend-base/blob/72d70535cf77e98be8f859aa5746c3dddb4d02d2/runtime/routing/utils.ts#L27-L50) walks `siteConfig.apps` in list order and each app's route tree depth-first, and returns the first route whose `handle.roles` includes the role. Only when no app declares the role does it read `siteConfig.externalRoutes`, again first match. There is no check for a second match and no warning, so when two apps declare the same role the one listed first in `apps` wins silently, and an external route for a role any app declares is never consulted.
- `resolveRouteByRole` and `getLinkProps` build on it, so every link resolved through a role follows the same order.
- [`ExternalRoute`](https://github.com/openedx/frontend-base/blob/72d70535cf77e98be8f859aa5746c3dddb4d02d2/types.ts#L11) is a role and a URL; nothing on it or on the site config says it should take precedence.

## What the docs say

- The migration guide's [URL Config changes](https://github.com/openedx/frontend-base/blob/72d70535cf77e98be8f859aa5746c3dddb4d02d2/docs/how_tos/migrate-frontend-app.md#url-config-changes): URLs "should now be expressed as part of the `apps` config as route roles, or as `externalRoutes`, and resolved in code via `resolveRouteByRole()`". It names both sources and does not say what happens when both declare a role.

## Where it bites

- Learning declares `org.openedx.frontend.role.courseDates`, `courseOutline` and `courseProgress` on its routes, which it must for the shell's course bar. Its progress tab links to the dates and outline tabs through those roles. A site that wants one of those links to go elsewhere cannot express that in site config: an external route for the role is never reached while Learning is installed.
- The same holds for any app that declares a role for a page it serves and any site that wants to point that role elsewhere.

## Questions

- Should a site be able to override an installed app's route for a role with a destination of its own, without uninstalling the app?
- If so, how does the site say so?
- Should the resolver report when two sources declare the same role?
