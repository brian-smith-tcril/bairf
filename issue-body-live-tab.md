## What moves

Files port from the legacy `src/` tree to the same relative path under `frontend-base/src/`, with their tests, and get a line each in `frontend-base/manifest.tsv`.

- The live tab ([`src/course-home/live-tab/`](https://github.com/openedx/frontend-app-learning/tree/master/src/course-home/live-tab)): one component that renders through the tab-page frame with the `lti_live` tab active and injects the iframe markup the LMS returns, sizing the embedded iframe to the viewport once it is in the document.
- The live query, its key and API function, into the course-home data module that #2189 established, as #2190 did for progress. The API reads `/api/course_live/iframe/<course id>/` on the LMS; the markup is absent when live is disabled for the course, and a 404 answers as an empty object, so the tab renders empty rather than erroring. `LMS_BASE_URL` becomes the site config's `lmsBaseUrl`; the tab reads no other config.

## What makes the tab appear

The tab exists only when the LMS lists it: `CourseLiveTab` is enabled when the course has a live configuration enabled, which course staff set in Studio under Pages & Resources, choosing a provider. Zoom takes per-course LTI credentials; BigBlueButton can run on site-wide credentials from the `COURSE_LIVE_GLOBAL_CREDENTIALS` setting. There is no waffle flag. The shell's course bar lists the tab from the LMS and, since its URL falls under Learning's root route, navigates to it client-side. The iframe markup is an LTI launch of the configured provider.

## Testing

The live tab tests port with the file and reach the page through the exported route array at the `live` path: the markup renders from the query, the embed is not refetched when the window regains focus, the sizing classes are re-applied when the markup changes, and the course metadata is requested once per load, with mocks per the conventions #2189 set.

The manual test needs a course with live configured. The manual-testing record carries the recipe: enable Live in Studio for the test course, choose a provider, and set credentials. Dummy credentials are enough to verify Learning's side, the tab in the course bar, the embed rendered and sized, and the launch posted to the provider URL; what the provider shows in return is the provider's.

## Acceptance

- [ ] On a course with live configured, the Live tab appears in the course bar and opens client-side; the provider's launch renders in a full-height iframe; on a course without it, the path renders the tab frame with no embed
- [ ] Types, lint and tests of the new package pass; the legacy workflow stays green; `npm run dev` from the package serves the live tab
- [ ] Manifest lines added for every file moved; the live-tab directory's coverage compared against the `master` baseline
