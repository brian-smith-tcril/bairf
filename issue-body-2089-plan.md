# Plan: #2089 — read `sections` and `coursewareMeta` from the courseware queries

Layers D3 + D4 of the #1977 model-store dissolution, as **two stacked layers
on top of #2134** (#2088 layer B):

- **Layer A — `coursewareMeta` + `sections` readers** (D3). "Part of #2089".
  The `useModel` / `useModels` readers, and the integrity-signature write.
- **Layer B — the owners' direct selectors and the mirrors** (D4). "Closes
  #2089". `CoursewareContainer.tsx` and `redirects.ts`, `modelReader.ts`, and
  the `meta.models` entries of both queries.
- **#2135 — declarative courseware redirects**, peeled out of this plan and
  stacked above layer B (decision B6).

Reviewed 2026-09-28; the four open questions and their outcomes are at the
end. Entry numbers become the `decisions-2089A.md` / `decisions-2089B.md`
numbering as each layer lands.

## How it works today

1. **`coursewareMeta[courseId]` is written by two queries, and both writes
   merge.** `useCoursewareMetadata` mirrors the whole `normalizeCoursewareMeta`
   result (`updateModel`); `useMinimalCourseOutline` mirrors its
   `courses[courseId]` entry, `{ id, title, sectionIds, hasScheduledContent }`
   (`updateModelsMap`). Both end in the slice's `update`,
   `{ ...existing, ...model }`, so neither drops the other's fields, and a
   field both write — `title` — takes the value of whichever response is
   dispatched second. `sections` comes only from the outline query
   (`addModelsMap`).

2. **Before #2023 the write order was fixed; since then it is the network's.**
   `fetchCourse` fetched the metadata, the outline, the course-home metadata
   and the sidebar toggles in one `Promise.allSettled` and dispatched after
   all four settled: the metadata first (a wholesale `addModel`), then the
   outline's `courses` on top. #2023 split them into independent queries,
   each mirrored as its own response arrives; it changed the metadata mirror
   to `updateModel` so a late metadata response could not drop `sectionIds`,
   and its test pins the metadata-last `title`. `CoursewareContainer` starts
   both fetches in one render, and `CourseExit` mounts fetching observers of
   both, so the race runs again on the course-end page.

3. **The two `title`s differ.** The courseware metadata endpoint's `name` is
   `display_name_with_default_escaped` (HTML-escaped, deprecated); the
   learning-sequences outline's `title` is written at publish from
   `display_name_with_default`, unescaped. Two readers put `title` in a page
   `<title>` as text — `Course.jsx` (the Helmet title) and
   `CourseCelebration.jsx` — so a course named "R&D" shows "R&amp;D" in the
   browser tab whenever the metadata response lands last.

4. **What changed since this issue was written.** #2088 layer B took the
   three `sequences` selectors, so layer B here has four: `coursewareMeta` in
   `CoursewareContainer.tsx`, and `sections` ×2 and `coursewareMeta` in
   `redirects.ts`. Two readers the task list does not name read through
   `modelKeys.coursewareMeta` (`Unit/constants.ts`): `UnitSuspense.tsx` and
   `useShouldDisplayHonorCode.js`. `SidebarContextProvider.jsx` is now
   `SidebarContext.tsx`. The `useModel('coursewareMeta', …)` example in
   `courseware/course/sidebar/README.md` was replaced by #2110.

5. **Two plugin-facing reads.** `SidebarProvider` passes each widget's
   `isAvailable` a `course` built as `{ ...coursewareMeta, ...courseHomeMeta }`
   — the merged model, outline fields included, though
   `SidebarWidgetContext.course` is typed `CourseHomeMeta & CoursewareMeta`.
   And `UpgradePanel` passes the `upgrade_panel.v1` slot
   `pluginProps.model: 'coursewareMeta'` (decision B5).

6. **The test store is seeded directly, not through the bridge.**
   `seedCoursewareModels` in `setupTest.js` dispatches into `state.models`
   itself, so the suites that read `state.models.*` for expected values keep
   working after the mirrors go; retiring the seeding is layer F. The suites
   that mock `useModel` for `coursewareMeta` (`UnitSuspense`,
   `useShouldDisplayHonorCode`, `UpgradePanel`) move with their readers.

## Layer A — `coursewareMeta` + `sections` readers (Part of #2089)

**A1. Each reader takes the query that owns the fields it reads.** With
`{ enabled: false }` at every reader (the owners, `CoursewareContainer` and
`CourseExit`, fetch both queries), and `?? {}` where a destructure stays:

| Reads | Files |
|---|---|
| Metadata only | `alerts/sequence-alerts/hooks.js`, `CertificateStatus.jsx`, `LockPaywall.jsx`, `sequence-navigation/hooks.js`, `course-outline/hooks.js`, `SocialIcons.jsx`, `UpgradePanel.jsx`, `UnitSuspense.tsx`, `useShouldDisplayHonorCode.js` |
| Outline only | `CourseBreadcrumbs.jsx` (`sectionIds` and the sections), `useSequenceIds` |
| Both | `Course.jsx` (`courseGoals`; `title` and the section), `Sequence.jsx` (`canAccessProctoredExams`, `license`; the section), `CourseExit.jsx` and `course-exit/utils.js` (`hasScheduledContent` from the outline, the rest from the metadata), `CourseCelebration.jsx` (`title` from the outline), `SidebarContext.tsx` (the merge, A3) |

`modelKeys` leaves `Unit/constants.ts` with its last key.

**A2. `title` is read from the outline, at every reader** (review outcome 1).
Faithful to the pre-#2023 write order, and fixes the escaped-name race
(mechanisms 2–3). The commit body describes it as restoring pre-#2023
behavior.

**A3. `SidebarContext.tsx` rebuilds the merge in `fetchCourse`'s order:**
`{ ...metadata, ...minimalCourseMetadata, ...courseHomeMeta }`, with
`courseHomeMeta` still last, and `SidebarWidgetContext.course` typed
`CourseHomeMeta & CoursewareMeta & MinimalCourseMetadata` so the type names
the fields the object has always carried.

**A4. The integrity-signature write moves onto the metadata query.**
`useSaveIntegritySignature`'s `onSuccess` becomes `setQueryData` on
`coursewareQueryKeys.metadata(courseId)` patching
`userNeedsIntegritySignature: false`, a no-op when nothing is cached (the
`updateSequenceUnit` semantics from #2088). `useDispatch` leaves
`courseware/data/apiHooks.ts`.

**A5. `useSequenceIds` and `CourseBreadcrumbs` read the outline once.**
`useSequenceIds` maps the course entry's `sectionIds` over the outline's
`sections`, gated on `useIsCourseLoaded` as today, through a disabled
observer — it is non-fetching by design (#2098, decision 4).
`CourseBreadcrumbs` gets the rewrite #2088 layer B left for here: the
sections read named on its own line, over the outline's map, with the dead
`?.` gone.

**A6. `CertificateStatus` keeps `{ enabled: false }`.** It renders on the
progress tab, where nothing fetches the courseware metadata, so its
`entranceExamData` stays `undefined` there as it does today.

**A7. Tests.** The `useModel` mocks become `useCoursewareMetadata` mocks
(`UnitSuspense`, `useShouldDisplayHonorCode`, `UpgradePanel`); `model-store`
mocks left with nothing to mock are removed (`SidebarContext.test`,
`UpgradeTrigger.test`, `UpgradeWidgetContext.test`,
`DiscussionsProvider.test`, each confirmed during implementation). #2098's
once-per-load request counts are checked to cover both queries on both
owner pages, adding any case missing. Negative check: one converted reader
flipped to fetching fails a count case.

**A8. Commit: `refactor!:` with a `BREAKING CHANGE:` footer.** For plugins:
`useModel('coursewareMeta', courseId)` and `useModel('sections', id)` keep
returning what the bridge writes until layer B; the replacements are
`useCoursewareMetadata(courseId, { enabled: false }).data` and
`useMinimalCourseOutline(courseId, { enabled: false }).data`. Learner-visible:
A2's title.

**A9. Manual test.** A course whose display name contains "&" shows it
unescaped in the tab title on every load, in courseware and on the
course-end page; the integrity-signature modal dismisses and stays
dismissed; breadcrumbs and the jump nav render; the course-exit modes and
the entrance-exam alert behave as before.

## Layer B — the owners' selectors and the mirrors (Closes #2089)

**B1. `CoursewareContainer` reads `celebrations` from `metadataQuery.data`.**
`CoursewareMeta.celebrations` names the one field a reader uses,
`firstSection`, following the rule that its sub-objects stay `unknown` until
a reader names their fields.

**B2. `redirects.ts` reads the sections and `sectionIds` from the outline
query it already holds.** `sectionViaSequenceId` stays a *section* looked up
by the route's sequence id — that is how a section-shaped URL is detected,
not a typo.

**B3. The mirrors go.** `modelReader.ts` is deleted; `useCoursewareMetadata`
loses its `meta`, and `useMinimalCourseOutline` keeps only `logStatusAs`.
The "coursewareMeta bridge" suite in `apiHooks.test.tsx` goes with them: it
pins the merge race that A2 removes.

**B4. `useSelector` leaves `src/courseware/`.** With A4, no `useSelector` or
`useDispatch` is left there.

**B5. The slots' `model` prop stays; losing the mirror behind it is a
`BREAKING CHANGE:`, not a deprecation** (review outcome 2). #1494
(SONIC-717) added `model` to the three upgrade-messaging slots, "passing
model as a prop to plugin slot for dynamic model selection": each value names
the model-store entry that slot's parent read its upgrade data from, so one
plugin component can sit in every slot and read the right entry through
`useModel(model, courseId)`. The slots' default content (`UpgradeNotification`
in all three) never read it; #1675 removed that content, and #1885 removed
the new-sidebar slot. Two slots pass `model` today:
`org.openedx.frontend.learning.upgrade_panel.v1` (`'coursewareMeta'`) and
`org.openedx.frontend.learning.course_outline_tab_notifications.v1`
(`'outline'`, whose mirror stays until #1999). FPF ADR 0003 defines a slot's
contract as its location, the type of content it wraps, and "the specific
set of `pluginProps` it exposes"; none changes here. What changes is what
the value reaches, which is this app's internals — the footing every earlier
layer's `useModel` change was released on. The PR description carries a
migration for plugin authors:

> A plugin that picked its model with the prop:
>
> ```jsx
> import { useModel } from '@src/generic/model-store';
>
> const ExamplePlugin = ({ courseId, model }) => {
>   const userHasPassingGrade = useModel(model, courseId).userHasPassingGrade;
>   return <p>userHasPassingGrade: {userHasPassingGrade ? 'Yes' : 'No'}</p>;
> };
> ```
>
> reads the query that owns that model instead:
>
> ```jsx
> import { useCoursewareMetadata } from '@src/courseware/data/apiHooks';
> import { useOutlineTabData } from '@src/course-home/data/apiHooks';
>
> const ExamplePlugin = ({ courseId, model }) => {
>   // Hooks can't be called conditionally, so read both. `enabled: false` means neither
>   // fetches: the page has already loaded its own, and the other stays empty.
>   const dataByModel = {
>     coursewareMeta: useCoursewareMetadata(courseId, { enabled: false }).data,
>     outline: useOutlineTabData(courseId, { enabled: false }).data,
>   };
>   const userHasPassingGrade = dataByModel[model]?.userHasPassingGrade;
>   return <p>userHasPassingGrade: {userHasPassingGrade ? 'Yes' : 'No'}</p>;
> };
> ```

**B6. The redirects' fire-once guards stay; #2135 replaces them** (review
outcome 3). Left in `src/courseware/` after B4 are `defaultMemoize` from
`reselect` and `shallowEqual` from `react-redux`, which keep each redirect
rule from re-firing on every render. The migration's end state has no
Redux-ecosystem dependency, so they go, but not as local copies: the guards
are dependency arrays by another name, and the tentative replacement is a
declarative resolver with the two lookups as queries. That is its own
question, stacked above this layer so it works on the inputs this layer
settles. This issue's check becomes: no `useSelector` / `useDispatch` in
`src/courseware/`.

**B7. Commit: `refactor!:` with a `BREAKING CHANGE:` footer.** For plugins:
nothing writes `coursewareMeta` or `sections` into the model store any more,
so `useModel('coursewareMeta', courseId)` returns `{}` and a direct
`state.models.coursewareMeta[courseId]` read throws; the replacements are
A8's, and B5's migration.

**B8. Manual test.** All five redirect rules still fire (resume,
section → sequence, section/unit → unit, unit → sequence/unit, outline
failure); the first-section celebration still records on crossing into the
next section.

## Review outcomes (2026-09-28)

1. **`title` source.** The outline, at every reader (A2, A3).
2. **The `upgrade_panel.v1` slot's `model` prop.** Kept; the mirror goes as a
   `BREAKING CHANGE:` with a plugin-author migration, no deprecation (B5).
   Removing the prop would change the slot's contract and is not done.
3. **`shallowEqual` / `reselect` in the redirects.** Out of this issue;
   peeled as #2135 with a declarative tentative plan (B6).
4. **Layer split.** As the issue has it: readers and the integrity write in
   A, the owners' selectors and the mirrors in B. Safe because the owners
   read only `celebrations` and `sectionIds`, which no mutation writes, so a
   store read left in A cannot go stale the way #2088's position read would
   have. A split by query (outline fields first, metadata second) was weighed
   and not taken: it touches `Course`, `CourseExit`, `course-exit/utils`,
   `CourseCelebration` and `SidebarContext` twice.
