An app cannot import `isClientRoute`, the check the course bar uses to tell whether a course tab's URL is a route in this site. Learning needs the same check for links inside its pages that point at a tab, so it now carries a copy (openedx/frontend-app-learning#2190, part of openedx/frontend-app-learning#1905). Importing it would be nicer than copying it.

## What the course bar does

- [`CourseTabsNavigation`](https://github.com/openedx/frontend-base/blob/72d70535cf77e98be8f859aa5746c3dddb4d02d2/shell/header/course-bar/navigation/CourseTabsNavigation.tsx#L35-L42) renders every tab in the `course_metadata` response. For each one it takes the pathname of `tab.url` and calls `isClientRoute(pathname)`: a tab whose path is a route in this site [renders as a react-router `Link`](https://github.com/openedx/frontend-base/blob/72d70535cf77e98be8f859aa5746c3dddb4d02d2/shell/header/course-bar/navigation/CourseTabsNavigation.tsx#L69-L73) to the path, and any other tab as an anchor to `tab.url`.
- [`isClientRoute`](https://github.com/openedx/frontend-base/blob/72d70535cf77e98be8f859aa5746c3dddb4d02d2/shell/header/course-bar/utils.ts#L46-L58) is true when the pathname matches, as a prefix, the route of a role some app provides under `providesCourseBarRolesId`. The masquerade bar's redirect [uses it too](https://github.com/openedx/frontend-base/blob/72d70535cf77e98be8f859aa5746c3dddb4d02d2/shell/header/course-bar/masquerade/hooks.ts#L173-L178).
- It is exported from `shell/header/course-bar/utils.ts` and from nowhere above it: neither [`shell/header/index.ts`](https://github.com/openedx/frontend-base/blob/72d70535cf77e98be8f859aa5746c3dddb4d02d2/shell/header/index.ts) nor [`shell/index.ts`](https://github.com/openedx/frontend-base/blob/72d70535cf77e98be8f859aa5746c3dddb4d02d2/shell/index.ts) names it, so `@openedx/frontend-base` does not export it.

## What Learning does

- Learning's progress page links to the dates and outline tabs from inside the page (its related links and the outline link under the detailed grades). The destinations are the same `tabs[].url` values the course bar reads, and the links are to behave as the tabs do: a `Link` when the URL is a route in this site, an anchor otherwise.
- `getLinkProps(url)` cannot make that choice from a tab's URL. The `course_metadata` response lists absolute URLs, and [`isInternalUrl`](https://github.com/openedx/frontend-base/blob/72d70535cf77e98be8f859aa5746c3dddb4d02d2/runtime/routing/utils.ts#L63-L65) accepts only a path, so every tab URL comes back as an anchor.
- So Learning repeats the course bar's check, built from what the package does export (`getProvidesAsStrings`, `providesCourseBarRolesId`, `getUrlByRouteRole`), and passes the resulting path or URL to `getLinkProps`:

  ```ts
  const isClientRoute = (pathname: string) => getProvidesAsStrings(providesCourseBarRolesId).some((role) => {
    const routePath = getUrlByRouteRole(role);
    return routePath !== null
      && routePath.startsWith('/')
      && matchPath({ path: routePath, end: false }, pathname) !== null;
  });

  export const getTabLinkUrl = (url?: string) => {
    if (!url) {
      return undefined;
    }
    const { pathname } = new URL(url);
    return isClientRoute(pathname) ? pathname : url;
  };
  ```

- The copy and the course bar agree only as long as neither changes.

## Question

- Can `isClientRoute` be exported from `@openedx/frontend-base`, so an app links to a tab by the same rule the course bar applies?
