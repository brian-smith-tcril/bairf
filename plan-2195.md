## What changes in the moved code

- **Every query spreads `queryDefaults`** (decision 30). `sequenceMetadataQuery` keeps its own `retry: false` after the spread.
- **Redirect destinations resolve Learning's roles (decision 38).** `coursewarePath` stays the one function the rules call. Its course form is the courseware role's URL, its sequence form is `getSequenceUrl`, and its unit form is a function added beside `getSequenceUrl` in `courseware/urls.ts`; decision 38 placed the unit form in #2196 with its first caller, and the first caller is here. The preview forms are the learning role's URL followed by `/preview/course/<ids>`, the prefix `TabPage` already builds for its access-denied redirect. The outline-failure rule resolves `courseOutlineRole` with the course id directly, without the tab-list gate of `useCourseOutlineUrl`, since `master` redirects there whatever `tabs` holds. The non-staff preview rule's `pathname.replace('/preview', '')` is unchanged: it removes the same segment from `/learning/preview/course/…`.
- **`useIsPreview`** compares the pathname with the learning role's URL followed by `/preview`; `startsWith('/preview')` is never true under `/learning`.
- **The wrappers.** `PathFixesProvider` becomes the element of a pathless layout route holding all of the `learning` route's children, since `master` wraps every route with it; the issue body says "around Learning's course routes" and is amended. `DecodePageRoute` becomes the element of the `course/:courseId` and `preview/course/:courseId` parents, which render a bare `<Outlet />` today, and keeps `PageWrap`, now frontend-base's; that restores the page event on every course route, the ported tabs included.
- **`DecodePageRoute` decodes every path segment and reads no route list.** Its body becomes: split `location.pathname` on `/`, pass each segment through `decodeUrl` (`master`'s helper, unchanged), rejoin, and render `<Navigate replace>` to the result when it differs. `master` finds the params by matching `location.pathname` against `DECODE_ROUTES`, the list its router is also built from; the package's router is built from the tree in `routes.tsx`, so a port has to change how the params are found either way, and decoding each segment needs no stand-in for the list. Weighed and not taken: `DECODE_ROUTES` ported into `constants.ts` and matched behind the learning role's URL (two definitions of the course routes, where `master` has one); the patterns built in `routes.tsx` from the two parents' `children` and passed as a prop (`master`'s algorithm kept, at the cost of a prop, a helper and a coupling to the tree's shape, to preserve a params-only decode whose comment on `master` is "it is just to be safe and less prone to errors"). Two differences from `master`, both read in react-router 6.30.6 (`@remix-run/router` 1.23.4) and not yet run, named in the layer's PR:
  - a course URL with a trailing slash is no longer redirected to the form without it. On `master` that is a side effect: `compilePath`'s matcher takes trailing slashes into the matched `pathname`, `generatePath` drops empty segments, and the two differ. The page renders at either form;
  - a percent-encoded character in a fixed segment (`learning`, `course`) is decoded and redirected, where `master`'s patterns do not match such a path and leave it.
  - Why `master` needs a pattern: `matchPath` returns the params raw (it only turns `%2F` into `/`), where the router's own matching (`matchRoutesImpl`) runs `decodePath` first, so `useParams()` in a layout route returns them already decoded once; `generatePath` takes the pattern as its first argument and does not encode; `useMatches()` carries each match's `id`, `pathname`, `params` and `handle`, and no pattern.
- **Routes.** The three courseware routes and two preview routes render the container through `lazy`, in one chunk; the `courseware` stub page goes. The preview index keeps its 404 loader.
- Corrected or restored where this issue's URL marks them: the two names in `courseware/data/index.js`, the factory index, the two `courseBlocks.factory.js` builders, the comment in `course-exit/utils.test.ts`.
