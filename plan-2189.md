# Plan: openedx/frontend-app-learning#2189 — port the dates tab

The plan block of the issue body, mirrored. Written 2026-10-22.

## Baseline

- The package at the top of #2221: the route tree with stubs, `learningCourse` on the course layout routes, no fetch, no provider, 29 tests, the suite failing on unexpected console output, the jest environment supplying the Fetch globals.
- On `master`, the dates tab's import closure (walked from `DatesTab.jsx`, `TabPage.tsx`, `LoadedTabPage.tsx`, `TabWithTimer.tsx` and `course-home/data/apiHooks.ts`, with the instructor toolbar, product tours, streak celebration, special-exams provider and the header, footer and tabs slots left out) is 44 source files; with their tests, factories and the Pact test, 72 files move. The root provider outside that closure, notices, comes with the root route.
- frontend-platform symbols the closure uses, all exported by `@openedx/frontend-base` from its root: `getAuthenticatedHttpClient`, `getAuthenticatedUser`, `getLoginRedirectUrl`, `sendTrackEvent`, `logError`, `logInfo`, `useIntl`, `FormattedMessage`, `defineMessages`, `getLocale`, `camelCaseObject`; `getConfig` becomes `getSiteConfig` or `getAppConfig(appId)` per key; `AppContext` becomes `SiteContext` (same `authenticatedUser` field). `history` appears only in tests.
- Config keys the closure reads: `LMS_BASE_URL` (23 sites) is `getSiteConfig().lmsBaseUrl`; `SITE_NAME` is `siteName`; `EXAMS_BASE_URL` (the onboarding and exam-attempt URLs in `course-home/data/api.ts`) and `ENABLE_NOTICES` are app config keys under their existing names, read through `getAppConfig(appId)`, with no bundled default, since `master` defaults both to `null` and the code treats unset the same way.

## Root route element

`Main.tsx` keeps the `CurrentAppProvider` and the outlet and gains the three Learning-wide providers in `master`'s nesting order: notices, user messages, toast. They mount once, only under `/learning`, and persist across client-side tab switches; nothing goes in `App.providers`, which the shell hoists site-wide, and the legacy query client provider is dropped since the shell owns one. The title message stays until a page sets its own through Helmet, as the loaded tab page does.

## Query client settings

`master` creates Learning's own query client (`src/queryClient.ts`), which retries a failed query up to three times except on a 4xx or a `NonRetryableError` (`shouldRetryQuery`), does not refetch on window focus, and logs each query's final failure with `logError`, or at the level its `meta.logStatusAs` names for that status. Under the shell, Learning's queries run on the shell's client, a `new QueryClient()` with the library's defaults: a 4xx is retried three times (1, 2 and 4 seconds apart, so an error page waits about seven seconds), every active query refetches when the window regains focus, and a failed query is logged nowhere. `src/queryClient.ts` ports to the same path without `createQueryClient`, and the settings move off the client:

- Retry and focus refetch go on each query, as the converted apps do (`retryUnlessClientError` in openedx/frontend-app-account's and openedx/frontend-app-profile's `src/data/queryOptions.js`; openedx/frontend-app-gradebook's `gradebookQueryOptions` in `src/data/query.ts`, which adds `refetchOnWindowFocus: false`). `queryClient.ts` exports `queryDefaults` (`retry: shouldRetryQuery`, `refetchOnWindowFocus: false`), spread first into every `queryOptions(...)` in `apiHooks.ts`, so a query's own setting still wins (`proctoringInfoDataQuery` keeps `retry: false`). Later ports spread it into the query definitions they bring.
- Logging cannot go on a query: TanStack Query 5 has no per-query error callback, and only the client's query cache sees a query's final failure. `Main.tsx` subscribes to the shell's query cache while Learning's root route is mounted and logs each `updated` event whose action is `error` (dispatched once, after retries, where the cache's `onError` runs) for queries whose key starts with Learning's `appId`, as every Learning query key does, with `master`'s logger table and `logStatusAs` lookup. The shell's queries and other apps' are never logged by Learning. None of the converted apps logs failed queries; Learning restores what `master` does.
- `master`'s `queryClient.test.ts` ports with them: `shouldRetryQuery`, the retry and focus behavior through `queryDefaults`, and the logging through the listener.

## Test conventions

This is the first page port, so its choices are the template for the rest.

- `src/setupTest.js` calls `initializeMockApp({ authenticatedUser })` and `addAppConfigs()` at top level, as profile and account do; the fail-on-console hook stays.
- **HTTP: the real mock-app client with `axios-mock-adapter`, not a per-file `jest.fn()`.** None of the converted apps has the adapter; profile, account, catalog, gradebook and learner dashboard replace `getAuthenticatedHttpClient` with a fake per file. Learning keeps the adapter: frontend-base's `MockAuthService` hands out a real `axios.create()` client and its own docstring's example wraps it in `axios-mock-adapter`; `master`'s 124 suites, its course-request harness and its request assertions on `axiosMock.history` are written for it, so porting is a move rather than a rewrite; and the error-path tests depend on real axios error shapes (`TabPage` branches on `response.status`), which a hand-built fake does not produce. `axios-mock-adapter` becomes a dev dependency; the deviation from the other apps is stated in the PR.
- `src/tests/`: `createTestQueryClient` and `seedQueryData` from `master`'s setup file, and the render helper grows to `master`'s wrapper shape (query client, intl provider, the three Learning providers, a memory router around the exported route array). `mockCourseRequests` waits for the courseware container, which is what it mocks. `mockLocation(members)` installs a copy of `window.location` with the members a test passes and returns it (jsdom cannot navigate, and its `Location` members are non-configurable), and the setup file restores the real location after each test; every ported test that stubs navigation goes through it.
- Each test file mocks `@openedx/frontend-base` by spreading `jest.requireActual` and overriding what it needs; no shared mock module; no Mock Service Worker. `master`'s plugin-framework mock is gone with the placeholder slots. `master`'s setup file silences two React deprecation messages (`defaultProps` on function components, `propTypes` on `forwardRef`); under the console hook each occurrence in the ported suites is either fixed in the component or, where it is Paragon's or react-fontawesome's, added to the silenced list under its upstream issue.
- The dates test reaches the page through the exported route array at the dates path, with the course-metadata and dates requests mocked; its `history` assertions become memory-router ones. The tab-page, alerts, user-messages, notices and data tests port at their seams.
- Access-denied redirects are tested where they are made, not in a page's suite. `getAccessDeniedRedirectUrl` (`shared/access.js`) maps the error code to a path, and `TabPage`, its only caller, prefixes the learning role's URL and navigates there; `master` tests both only through the "when receiving an access denied error" block of `DatesTab.test.jsx` (six codes) and the "when receiving a course_access error_code" block of `CoursewareContainer.test.jsx` (nine), both from #558, and `access.js` has no test. The port drops the Dates block; a new `shared/access.test.ts` covers every code, the fallback, and the outline's no-redirect case; `TabPage.test.jsx` asserts that a denied course lands at the learning role's URL plus that path; and `api.test.js` asserts that the metadata response's `course_access` arrives as the `courseAccess` `TabPage` reads, which the page blocks covered by starting from the server's shape. The courseware block goes when #2195 ports that test.
- Route tests assert `expect(runPageRules(document)).toEqual([])` once the page has rendered: `routes.test.tsx` at every path it covers (from #2221), the dates test at the dates path. `runPageRules` and its first rule, `mainLandmark` (more than one `<main>` without `hidden` is an error, none is a warning), come from openedx/frontend-base#329, first published in `2.0.0-alpha.17`, which #2217's scaffold commit locks.
- Pact: the consumer test and the contract it writes are dropped (`dropped` manifest lines for the test, `src/pacts/constants.js` and `src/pacts/frontend-app-learning-lms.json`). The contract is published and verified by nothing (openedx-platform's only Pact verifier loads its own xblock-handler contract; `master` has no broker, stub script or CI step), its committed file is stale, and `api.test.js` covers the two functions the test exercised.

## Coverage

The bar is the package's global `lines: 96.15` threshold from #2187, met at the top of the PR; there are no per-directory thresholds. Code the PR ports is covered by tests in the commit that ports it, placed beside the code they test: where `master` covered a file only through another tab's suite, the port adds the test next to the file (`api.test.js` and `courseHomeOutline.test.ts` for the outline, progress, goal and search functions; the frame's notices, alert, user-messages and toast files; the dates files). A line whose test would be contrived may stay uncovered while the bar is met; the PR names each one. Factories are counted like any file: one no test builds is unused, and moves with the first test that builds it (What moves).
