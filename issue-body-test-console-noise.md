Part of #1905.

**Goal:** the frontend-base package's test suite fails a test that prints an unexpected `console.warn` or `console.error`, so every later port lands with a silent suite and the noise `master`'s suite has accumulated does not move across with the tests.

**Why now:** one run of `master`'s suite (124 suites, 1279 tests, 2026-10-21) prints 2,101 jest console blocks: 960 warnings, 296 errors, 845 logs. About half go away by construction under frontend-base (the legacy test setup logs every mocked request and routes the logger mocks to `console.log`; frontend-platform's config checks and its second copy of `pubsub-js`; the header package's `NotificationsTray`). The other half is real: a Paragon deprecation in the course home tour (566 blocks), hover-only overlays in the grade summary (134), both outline normalizers logging the root `course` block (138), and some 250 test-code problems such as missing required props, un-awaited updates and timers advanced without fake timers. Each of those is fixed in the port that carries its file, and a hook that fails on console output is what makes a port fix it instead of carrying it. The package is clean today (2 blocks, both react-router's future flag warnings), so the hook starts clean.

## Baseline

- The package at the top of #2217 (`f8a64c1e`): 2 tests, 100% lines, and 2 console blocks per run, both react-router 6's future flag warnings printed when `Main.test.tsx` mounts a `BrowserRouter`. Nothing else prints.

About half go away by construction under frontend-base; the rest are app and test defects that the ports fix file by file. The inventory with every message, its emitter and its fate is kept with the effort's working notes.
- `jest-fail-on-console` 3.3.4 (2025-12-16), no dependencies, peer `@jest/globals >=27.5.1`, which jest 29's tree provides.

## Mechanism

- `jest-fail-on-console` as a dev dependency of `frontend-base/`, called once in `src/setupTest.js`, which `jest.config.js` already lists in `setupFilesAfterEnv`. Defaults do what the issue asks: a test fails when it calls `console.error` or `console.warn`; `console.log`, `info`, `debug` and `assert` are left alone.
- `silenceMessage` returns true for a message starting with `⚠️ React Router Future Flag Warning`, so those two messages neither print nor fail. `silenceMessage` rather than `allowMessage`, because `allowMessage` keeps printing ("the message will show in the console and the test won't fail"), and the point is a silent suite. The matcher carries a comment naming openedx/frontend-base#325 and saying the entry goes when that is resolved. This list is the only place tolerated output lives; a later entry needs the same comment saying whose warning it is.
- A test whose point is the output mutes the console for that test, the README's own recommendation: `jest.spyOn(console, 'error').mockImplementation(() => {})` in the test and `mockRestore()` at its end (the jest config does not restore mocks automatically), with the call asserted where the message is the behavior under test. The library's failure message says which method printed what, which is all a port needs to find this rule in the issue.
