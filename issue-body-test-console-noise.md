Part of #1905.

**Goal:** the frontend-base package's test suite fails a test that prints an unexpected `console.warn` or `console.error`, so every later port lands with a silent suite and the noise `master`'s suite has accumulated does not move across with the tests.

**Why now:** one run of `master`'s suite (124 suites, 1279 tests, 2026-10-21) prints 2,101 jest console blocks: 960 warnings, 296 errors, 845 logs. About half go away by construction under frontend-base (the legacy test setup logs every mocked request and routes the logger mocks to `console.log`; frontend-platform's config checks and its second copy of `pubsub-js`; the header package's `NotificationsTray`). The other half is real: a Paragon deprecation in the course home tour (566 blocks), hover-only overlays in the grade summary (134), both outline normalizers logging the root `course` block (138), and some 250 test-code problems such as missing required props, un-awaited updates and timers advanced without fake timers. Each of those is fixed in the port that carries its file, and a hook that fails on console output is what makes a port fix it instead of carrying it. The package is clean today (2 blocks, both react-router's future-flag warnings), so the hook starts clean.

## Mechanism

- `jest-fail-on-console` as a dev dependency of `frontend-base/`, registered in `src/setupTest.js`: a test that prints to `console.error` or `console.warn` fails with the printed message. `console.log` is not failed; lint keeps it out of `src/` and test-time logging stays available.
- An allowlist by message, the one place noise is tolerated, each entry with a comment saying whose it is. The first two entries are react-router 6's future-flag warnings (`v7_startTransition`, `v7_relativeSplatPath`), printed by any router created without `future` flags. Learning does not create the runtime router, the frontend-base shell does, and the flags change behavior, so whether and when to opt in is frontend-base's call; an issue is filed there to track it, and these two entries go when it is resolved.
- A test whose point is the output (an error-boundary test, a "logs on 404" test) mocks `console.error` for that test, which also documents the intent. The convention is stated in the package's test setup file.

## Test conventions this adds to

The package's tests follow the converted apps' conventions: each test file mocks `@openedx/frontend-base` by spreading `jest.requireActual`, no shared mock module, no Mock Service Worker, the HTTP client a per-file mock, a shared render helper for the query client, intl provider and memory router, and assertions that only test shell responsibilities dropped. This layer adds one rule: the suite fails on unexpected console output, and a port that mutes the console in a test says why in the test. None of the converted apps (account, catalog, profile, instructor dashboard) enforces this; the deviation is justified by the state of `master`'s suite above.

## Not in scope

- Fixing any of `master`'s warnings on `master`; each is fixed in the port that moves its file.
- The runtime warnings in the browser console; those are the shell's router and belong to frontend-base.

## Acceptance

- [ ] `npm test` in `frontend-base/` fails a test that prints an unexpected `console.warn` or `console.error`, demonstrated by a throwaway test in the PR and then removed
- [ ] The two react-router future-flag messages are allowlisted with a comment pointing at the frontend-base issue
- [ ] The package's suite passes with no console output
- [ ] The convention for muting the console in a test is written in the setup file
