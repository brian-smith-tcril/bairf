Decisions settled in review, refining the task list above:

- **Three read shapes, not one.** `TabPage` and `DatesTab` already hold the owner's query (`courseStatus.metadataQuery` / the `metadataQuery` fetched two lines up), so they read `metadataQuery.data ?? {}` rather than adding a second observer of the same key — what `DatesTab` did for its tab payload in #2083. `useEnrollmentAlert` and `usePrivateCourseAlert` put the whole `course` object in a `useMemo` dependency array, so they read `.data` with no `?? {}` (`decisions-2083.md` entry 8). The other 27 sites take `useCourseHomeMeta(courseId, { enabled: false }).data ?? {}`.
- **`useCourseHomeMeta` gains a partial `CourseHomeMeta` type with required fields.** Unlike `OutlineTabData`, whose fields are optional because that endpoint's 403 branch returns `{}`, the metadata endpoint always sends the whole serializer; "not loaded" is `data === undefined`, not optional fields. Names only what the TypeScript readers need, with an index signature so plugins are not limited to our list.
- **The two `.tsx` readers follow the TanStack docs, not a default.** `LoadedTabPage` renders only after the owner's query settled, so it keeps the query result and narrows on `isSuccess` ([TypeScript › Type Narrowing](https://tanstack.com/query/latest/docs/framework/react/typescript#type-narrowing)); a disabled observer over a populated cache starts in that state ([Disabling/Pausing Queries](https://tanstack.com/query/latest/docs/framework/react/guides/disabling-queries)). If it is not in success it throws, the `Section.tsx` shape from #2083. `TabPage` renders its header while pending, so it keeps `?? {}`, typed as `Partial<CourseHomeMeta>`. `useToggle` takes a boolean, so `useToggle(!!streakLengthToCelebrate)` — also what `ProductTours`' `bool.isRequired` prop already asked for.
- **The tab-URL hooks (per the comment above) do not fetch.** `useCourseOutlineUrl`, `useDatesTabUrl` and `useProgressTabUrl` in `course-tabs/hooks.ts` read with `{ enabled: false }`, like every other reader here and `useProgressData()` after #2103. `RelatedLinks` and `DetailedGrades` use them; `CertificateStatusAlert` calls `useProgressTabUrl()` at the top of the component (a hook cannot live in the `renderNotPassingCourseEnded` branch) and `tabs` leaves its payload. `LoadedTabPage` keeps `tabs` — the nav slot takes the array.
- **A request-count case in every owner page's suite.** Outline, dates, progress, discussion, live, `CoursewareContainer` and `CourseExit` each get *requests the course metadata once per load* (wait for `isFetching() === 0`, then exactly one GET), #2103's shape. The property is per page — a forgotten `{ enabled: false }` in `Day.jsx` shows up only on the dates page — so one representative case was rejected.
- **#2107 goes first.** `LoadedTabPage.test.jsx`'s streak case has never been able to fail (unconditional mock since #354; fixture inert since AA-1018). It is fixed in its own `test:` layer below this one, so this layer's change to that suite is only the data-source swap.
- **`CoursewareSearch.test.jsx` mocks the hook.** A like-for-like swap of its `useModel` mock for a `useCourseHomeMeta` mock returning `{ data: { org } }`, the shape `CourseAccessErrorPage.test.jsx` already uses; the suite mocks every hook the component calls and has no endpoint handlers.
- **`refactor:`, not `refactor!:`.** Who reads moves; nothing fetches differently; the bridge entry stays until B3, so `useModel('courseHomeMeta')` keeps working for plugins. The window in which `LoadedTabPage` reads `celebrations` from the query while the two celebration writers still target the store (until B3) was traced and has no visible effect.

## Context

### How it works today

`useCourseHomeMeta` (`course-home/data/apiHooks.ts:70-81`) is the metadata
query. Since #2098 it takes `{ enabled }`, and it still carries the bridge
entry that mirrors every result into the model store:

```ts
export const useCourseHomeMeta = (
  courseId: string | undefined,
  { enabled = true }: QueryOptions = {},
) => useQuery<
{ courseAccess?: { hasAccess: boolean } },
RequestError
>({
  queryKey: courseHomeQueryKeys.metadata(courseId!),
  queryFn: () => getCourseHomeCourseMetadata(courseId),
  enabled: enabled && !!courseId,
  meta: { modelType: 'courseHomeMeta', courseId },
});
```

`bridgeToModelStore` (`data/modelStoreBridge.ts:42-45`) dispatches
`addModel({ modelType: 'courseHomeMeta', model: { id: courseId, ...data } })`
on every successful fetch. The 53 `useModel('courseHomeMeta', courseId)` reads
in `src/` read that mirror through `useSelector`, and `useModel` returns a
referentially stable `{}` when the model is absent
(`generic/model-store/hooks.js:6-11`).

### Why `{ enabled: false }` at the readers

Same reasoning as `decisions-2083.md` entry 3 and `decisions-2098.md` entry 4.
Every B2 site mounts after its owner's fetch has settled (the gate), so a
fetching observer would find the entry stale at `staleTime: 0` and refetch on
mount — the two-requests-per-load defect #2083 fixed for the tab payloads and
#2098 for the courseware gate. Today the `course_metadata` count is one per
page load — #2098 measured the outline → courseware crossing going from three
to one (`manual-testing-2098.md:118`) — and this layer must keep it there. `useIsCourseLoaded` already reads this query with
`{ enabled: false }`, so the shape is established on this hook.

## The change

### 1. `useCourseHomeMeta` gets a partial `CourseHomeMeta` type

Following `OutlineTabData` (`apiHooks.ts:108-114`, `decisions-2083.md` entries
9 and 11) in scope: a partial interface naming only the fields this repo's
TypeScript readers need, with an index signature so plugins importing the hook
are not limited to our list. Exported, because `TabPage`'s `CourseStatus` type
needs it:

```ts
export interface CourseHomeMeta {
  celebrations: {
    streakLengthToCelebrate?: number | null;
    streakDiscountEnabled?: boolean;
  } | null;
  courseAccess: { hasAccess: boolean };
  hasCourseAuthorAccess: boolean;
  number: string;
  org: string;
  originalUserIsStaff: boolean;
  start: string;
  tabs: TabMetadata[];
  title: string;
  verifiedMode: Record<string, unknown> | null;   // see open question 1
  [key: string]: unknown;
}
```

Unlike `OutlineTabData`, the named fields are **required**. The outline type is
all-optional because that endpoint's 403 branch returns `{}`; the metadata
endpoint has no such branch (`api.js:96-101` returns the whole serializer,
camel-cased), so required fields are the accurate type. "Not loaded yet" is
expressed the way React Query expresses it — `data` is `undefined` and
`isSuccess` is `false` — not by making every field optional. `TabMetadata`
comes from `course-tabs/utils.ts:1-5` (B1). The comment above the hook ("other
course-home fields are read via `useModel`/the bridge (until #1977)") is
replaced by the `OutlineTabData` comment's wording. `CourseStatus.metadataQuery`
(`TabPage.tsx:25`) becomes `UseQueryResult<CourseHomeMeta, RequestError>`;
every caller already passes the hook's result, so nothing else changes type.
`useIsCourseLoaded`'s `courseAccess?.hasAccess` read is unaffected.

## Open questions

1. **How the two `.tsx` readers get typed data — recommended: narrow on
   `isSuccess` in `LoadedTabPage`; a `Partial` default in `TabPage`.** The
   `.jsx` sites' `data ?? {}` does not carry over: it widens to
   `CourseHomeMeta | {}`, which TypeScript will not destructure
   (`decisions-2083.md` entry 10). The React Query docs' answer to "when is
   `data` defined" is the status discriminant, not a default:

   > React Query uses a discriminated union type for the query result,
   > discriminated by the `status` field and the derived status boolean
   > flags. This will allow you to check for e.g. `success` status to make
   > `data` defined.
   > — [TypeScript › Type Narrowing](https://tanstack.com/query/latest/docs/framework/react/typescript#type-narrowing)

   and a disabled observer is in that state whenever its owner has populated
   the cache:

   > If the query has cached data, then the query will be initialized in the
   > `status === 'success'` or `isSuccess` state.
   > — [Disabling/Pausing Queries](https://tanstack.com/query/latest/docs/framework/react/guides/disabling-queries)

   **`LoadedTabPage`** renders only after `TabPage` has seen the owner's query
   settle, so the docs' shape applies directly, and the guard doubles as the
   `tabs` guard open question 2 needed:

   ```ts
   const metadataQuery = useCourseHomeMeta(courseId, { enabled: false });
   const streakLengthToCelebrate = metadataQuery.data?.celebrations?.streakLengthToCelebrate;
   const [isStreakCelebrationOpen,, closeStreakCelebration] = useToggle(!!streakLengthToCelebrate);
   const logistrationAlert = useLogistrationAlert(courseId);
   const enrollmentAlert = useEnrollmentAlert(courseId);

   if (!metadataQuery.isSuccess) {
     throw new Error(`LoadedTabPage rendered without course metadata for ${courseId}`);
   }
   const {
     celebrations, org, originalUserIsStaff, tabs, title, verifiedMode, hasCourseAuthorAccess,
   } = metadataQuery.data;
   ```

   After the guard `data` is `CourseHomeMeta`, so with required fields (§1)
   `tabs` is `TabMetadata[]` and the nav slot's prop type-checks with no
   coercion. The throw is our addition, following `Section.tsx:50-52` from
   #2083: today, rendered without the model, `LoadedTabPage` throws inside
   `CourseTabLinksList` on `tabs.map` (`CourseTabLinksList.tsx:13`), and
   production never gets there; the guard keeps that loudness one level up
   with a message that names the course. The one wrinkle is `useToggle`,
   whose initial value is needed before the guard because hooks cannot follow
   an early throw — hence the single optional-chained read above the hooks.
   Two consequences to settle with it:

   - `useToggle(!!streakLengthToCelebrate)`: Paragon's `useToggle` takes
     `defaultIsOn?: boolean` (`useToggleHook.d.ts`) and the value is
     `number | null | undefined`. The toggle's state becomes `true` instead of
     `3`; its consumers are `!!isStreakCelebrationOpen` (already coerced,
     `:75`) and `ProductTours`' `isStreakCelebrationOpen` (`:58`), which is
     `PropTypes.bool.isRequired` (`ProductTours.jsx:208`) and used as a bare
     condition (`:112`) — so the coercion is what the prop already asked for,
     and it removes a `PropTypes` type warning that fires today whenever a
     streak is pending.
   - `verifiedMode` is used as a truthy operand at `:50` and passed to the
     untyped `StreakModal`; the index signature would make it `unknown`, which
     `&&` rejects, so it is a named field. `Record<string, unknown> | null` is
     enough until B3 types the modal's own reads.

   **`TabPage`** is the reader that genuinely renders while the query is
   pending (`HeaderSlot` at `:140`), so narrowing does not apply and the
   docs offer nothing for a default. It keeps the `?? {}` shape the `.jsx`
   sites use, typed honestly as partial on the binding:

   ```ts
   const {
     courseAccess, number, org, start, title,
   }: Partial<CourseHomeMeta> = courseStatus.metadataQuery.data ?? {};
   ```

   `{}` is assignable to `Partial<CourseHomeMeta>`, every binding is
   `T | undefined`, and `org`/`number`/`title` reach `HeaderSlot` as
   `undefined` while pending exactly as the store's `{}` gave them today.
   `getAccessDeniedRedirectUrl` is JavaScript and runs only under `isDenied`,
   which implies the query settled.

   Rejected: `data!` or a cast at the read (the shape `decisions-2083.md`
   entry 13 exists to prevent); optional chaining per field in `LoadedTabPage`
   (seven chained reads rewriting a block the docs' shape leaves intact); an
   all-optional `CourseHomeMeta` with an annotated destructure in both files
   (types the endpoint as something it is not, and still leaves `tabs`
   possibly undefined at the slot).
