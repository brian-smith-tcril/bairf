## 2. How `provides` reaches the course bar

**Ids** (`shell/header/constants.ts:1–3`, re-exported `shell/header/index.ts:2` and `shell/index.ts:10–11`):

- `providesCourseBarRolesId = 'org.openedx.frontend.provides.courseBarRoles.v1'`
- `providesCourseBarMasqueradeRolesId = 'org.openedx.frontend.provides.courseBarMasqueradeRoles.v1'`

**Collection.** `App.provides?: Record<string, unknown>` (`types.ts:37`). `getProvides(id)` walks `getSiteConfig().apps` and collects `app.provides[id]` (`runtime/config/index.ts:437–447`); `getProvidesAsStrings(id)` keeps string and string-array values and flattens (458–461). ADR 0013, Decision: "a flat key-value map where each key is a namespaced identifier agreed upon by the providing and consuming apps ... The runtime stores this data and exposes it through a runtime function, but does not interpret it" (lines 58–61).

**Consumption** (`shell/header/course-bar/utils.ts`):

- `getCourseBarRoles()` = `getProvidesAsStrings(providesCourseBarRolesId)` (13–15).
- `getCourseBarMasqueradeRoles()` = masquerade list filtered to roles also in the course-bar list (30–34); ADR 0013 lines 121–127: "Masquerade is therefore a refinement of the course bar: a role only present in the masquerade list ... is ignored."
- `isCourseBarRoute()` / `isCourseBarMasqueradeRoute()`: any provided role ∈ `getActiveRoles()` (36–44). Active roles = `handle.roles` of **every matched route, ancestors included** (`runtime/react/hooks/useActiveRouteRoleWatcher.ts:9–21`) plus widget roles (`runtime/config/index.ts:426–428`).
- `isClientRoute(pathname)`: for each course-bar role, `getUrlByRouteRole(role)` (first route, depth-first across apps in order, whose `handle.roles` includes the role; path = concatenated ancestor segments; `null` when none — `runtime/routing/utils.ts:8–50`), and `matchPath({ path, end: false }, pathname)` (51–58).

**What `CourseTabsNavigation` does with them** (`course-bar/navigation/CourseTabsNavigation.tsx`): the widget is only mounted when `isCourseBarRoute()` is true (`app.tsx:184–186`). It fetches the LMS tab list, and for each tab sets `clientPath = isClientRoute(pathname) ? pathname : null` (35–42); a tab with a `clientPath` renders `<Nav.Link as={Link} to>`, otherwise `<Nav.Link href={tab.url}>` (69–73). Active tab comes from `findActiveTab` on the URL, independent of roles (44–47).

**A tab whose role no installed app provides** is still listed (the list comes from the LMS, not from `provides`) and renders as a plain anchor to the absolute LMS URL — a full page load (`CourseTabsNavigation.test.tsx:91–97`: `href` equals `${LMS_BASE}/instructor-dashboard/.../course_info` when `isClientRoute` is false). When **no** app provides any role the bar is not mounted at all (`utils.test.ts:43` "returns false when no providers exist"; `app.tsx:184–186`).

**What `MasqueradeBar` does with them**: mounted when `authenticated` and `isCourseBarMasqueradeRoute()` (`app.tsx:193–196`). After a successful masquerade POST it refetches the tab list and, if the current pathname is under no tab, goes to the first tab: `navigate()` when `isClientRoute(targetPath)`, else `window.location.assign(fallback.url)` (`hooks.ts:161–178`).

**Worked example** (`frontend-app-instructor-dashboard`): `src/constants.ts:2` `instructorDashboardRole = 'org.openedx.frontend.role.instructorDashboard'`; `src/routes.tsx:62` `handle: { roles: [instructorDashboardRole] }`; `src/provides.ts:4–7` declares both ids with that single role (a bare string, which `getProvidesAsStrings` accepts); `src/app.ts:7–12` passes `provides` on the `App`. Gradebook declares a route role (`src/routes.tsx:12–14`) but no `provides` (`src/app.ts:6–10`), so no course bar renders there.

**What Learning declares.** Learning has no route roles today (`src/index.jsx:57–136` are plain `<Route>`s; no `org.openedx.frontend.role` string in `src/`). Role ids are Learning's to name; the existing convention is `org.openedx.frontend.role.<name>` (`shell/constants.ts:1–4`, instructor dashboard above, gradebook `src/routes.tsx:13`; the `utils.ts:10` comment uses `org.openedx.frontend.role.learning`). With one role per tab route, mirroring the `activeTabSlug` each page passes (`DatesTab.jsx:50`, `DiscussionTab.jsx:39`, `LiveTab.jsx:40` = `lti_live`, `OutlineTab.jsx:205`, `ProgressTab.jsx:72`, `CoursewareContainer.tsx:71`, `CourseExit.jsx:84`):

```ts
import { providesCourseBarMasqueradeRolesId, providesCourseBarRolesId } from '@openedx/frontend-base';

const courseBarRoles = [
  'org.openedx.frontend.role.learning.outline',     // DECODE_ROUTES.HOME        /course/:courseId/home
  'org.openedx.frontend.role.learning.dates',       // DECODE_ROUTES.DATES       /course/:courseId/dates
  'org.openedx.frontend.role.learning.progress',    // DECODE_ROUTES.PROGRESS    /course/:courseId/progress(/:targetUserId/)
  'org.openedx.frontend.role.learning.discussion',  // DECODE_ROUTES.DISCUSSION  /course/:courseId/discussion/:path/*
  'org.openedx.frontend.role.learning.live',        // DECODE_ROUTES.LIVE        /course/:courseId/live
  'org.openedx.frontend.role.learning.courseware',  // DECODE_ROUTES.COURSEWARE  /course/:courseId(/:sequenceId(/:unitId)), /preview/..., COURSE_END
];

const provides = {
  [providesCourseBarRolesId]: courseBarRoles,
  [providesCourseBarMasqueradeRolesId]: courseBarRoles,
};
```

Each string must also appear in `handle.roles` of the matching route (`types.ts:16–23`; paths from `src/constants.ts:3–20`). The masquerade list equals the course-bar list because `InstructorToolbar` renders on every `TabPage` today (`LoadedTabPage.tsx:72`). Facts bearing on each entry:

- `outline`: the LMS tab with `tab_id: courseware` points at the outline (Learning reads its URL as the outline URL, `course-tabs/utils.ts:26`); the shell renames it to `outline` (`service.ts:29`). `isClientRoute` matches its pathname against the `HOME` route path.
- `discussion`: the route pattern requires a `:path` segment (`constants.ts:8`); `matchPath({ path, end: false })` against a tab pathname lacking that segment does not match, so the tab renders as `href`.
- `courseware`: no LMS tab URL falls under these routes except via `outline`; the role matters for `isCourseBarRoute`/`isCourseBarMasqueradeRoute` on unit, sequence and course-end pages, not for client-routing a tab.
- A single role on the root `learning` route would also satisfy both checks: the watcher collects ancestor roles (`useActiveRouteRoleWatcher.ts:11–17`) and `getUrlByRouteRole` would return `/learning`, which `matchPath(..., end: false)` prefix-matches for every tab pathname under it. `getUrlByRouteRole` returns the **first** route carrying a role (`utils.ts:8–25`), so one role cannot resolve to two paths.

## 3. Footer

Learning renders `FooterSlot` from the footer package on `TabPage.tsx:158`, `PageNotFound.jsx:44` and `CourseAccessErrorPage.jsx:26,45`, with no props; `GoalUnsubscribe.jsx` and `preferences-unsubscribe/index.jsx` render no footer. `src/plugin-slots/FooterSlot/README.md` documents slot id `org.openedx.frontend.layout.footer.v1` (aliases `footer_slot`, `footer_plugin_slot`, `FooterSlot/index.jsx:7–8`). `src/index.scss:3` imports the package CSS; `:40–42` sets `footer { flex: 0 }`.

What that renders (`components/Footer.jsx:40–66`): `<footer role="contentinfo" class="footer d-flex border-top py-3 px-4">`; one link to `LMS_BASE_URL` showing `LOGO_TRADEMARK_URL` (alt from messages, max-height 45px); the click sends track event `edx.bi.footer.link` with `category: 'outbound_link'` (16–18, 30–38); `LanguageSelector` only when `supportedLanguages` and `onLanguageSelected` are passed (28, 59–64) — Learning passes neither, so none.

Shell footer: `shell/footer/Footer.tsx:4` is a single slot; `DesktopFooterLayout.tsx:16–37` composes a top `RevealLinks` collapsible (a bare border when empty, `RevealLinks.tsx:13–17`), left `Logo` (`app.tsx:54–60`, same `shell/Logo.tsx` as the header: `headerLogoImageUrl`, destination `homeRole` route or `/`), four labeled center link columns (null when empty, `LabeledLinkColumn.tsx:120–122`), `LegalNotices` with `CopyrightNotice` (`siteName`, `CopyrightNotice.tsx:74–96`) and a trademark notice marked "cannot be removed or modified" (`LegalNotices.tsx:56–57`), right `LanguageMenu` (`app.tsx:62–68`) and `PoweredBy` Open edX image (`PoweredBy.tsx:102–112`). ADR 0016 (lines 55–71) makes the whole footer replaceable via `org.openedx.frontend.widget.footer.desktopLayout.v1` / `org.openedx.frontend.slot.footer.desktop.v1`.

What Learning's `FooterSlot` renders that the shell footer does not: the logo link to `LMS_BASE_URL` (shell: `homeRole` or `/`); the `LOGO_TRADEMARK_URL` image (shell: the header logo image); the `edx.bi.footer.link` track event; the `org.openedx.frontend.layout.footer.v1` plugin slot. Shell additions with no Learning counterpart: copyright, trademark notice, PoweredBy, language menu, link columns; and the shell footer renders on every non-chromeless route (`shell/app.ts:34–42`), including the two unsubscribe pages that have no footer today.
