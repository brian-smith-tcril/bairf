Part of #1905. Depends on #2197.

**Goal:** a learner in courseware on a frontend-base site opens the auxiliary sidebar (the panel beside the content that holds the registered widgets; `RightSidebarSlot` in the code) and finds the in-context discussions panel on units that have discussions enabled, as on `master`. Operators can still register their own widgets and disable built-in ones, and the framework's handling of several registered widgets at once (one trigger each, one panel open) ports with it. The auxiliary sidebar stubs from #2196 are replaced. The upgrade widget is not ported here: its panel is a plugin slot with no default content (since [14c662dc](https://github.com/openedx/frontend-app-learning/commit/14c662dc530c1982d016a2ffd2ffe2af51603303)), so it ports with the Slot API in #2185, where whether it stays registered by default is settled alongside #1902.

## What moves

Files port from the legacy `src/` tree to the same relative path under `frontend-base/src/`, with their tests, and get a line each in `frontend-base/manifest.tsv`.

- The auxiliary sidebar and its trigger: the generic sidebar and trigger shells the framework from #2197 already holds, now rendered through the auxiliary sidebar slot and its trigger slot (`RightSidebarSlot` and `RightSidebarTriggerSlot`, keeping their names), which become placeholder slots with those shells as their default content.
- The widget registry's defaults ([`defaultWidgets.js`](https://github.com/openedx/frontend-app-learning/blob/master/src/courseware/course/sidebar/defaultWidgets.js)), un-stubbed from #2197 with the discussions widget as the one registered default: each widget is a sidebar, a trigger, a provider and an availability check, sorted by priority. The upgrade widget's entry stays out until #2185.
- The discussions widget ([`src/widgets/discussions/`](https://github.com/openedx/frontend-app-learning/tree/master/src/widgets/discussions)): available on a unit with in-context discussions enabled; its sidebar embeds the discussions app for the unit's topic. Its URL comes from the discussions role, resolved through frontend-base's route resolver (an external route a site supplies today, the installed discussions app later), in place of `DISCUSSIONS_MFE_BASE_URL`.

## Operator configuration

On `master` operators add external widgets and disable built-in ones through a `SIDEBAR_WIDGETS` list read from the runtime config, documented in the sidebar framework's README. Under frontend-base that list is read from Learning's app config under the same key; the shape of each entry is unchanged, since app config is JavaScript as the legacy plugin config file was. The README is updated to say where the list now lives. The location change is an operator-facing change and is noted as such; it is not a change to what can be configured.

## Testing

The tests of the files that move here, the discussions widget's and the auxiliary sidebar slots', port with them, as do the framework's mock-widget suites (`SidebarTriggers.test.jsx`, `defaultWidgets.test.js`) that register two or more widgets, and reach the page through the exported route array at a unit URL, with the unit, course metadata and discussions-topic queries mocked per the conventions #2189 set.
