Part of #1905. Depends on #2197.

**Goal:** a learner in courseware on a frontend-base site opens the auxiliary sidebar (the panel beside the content that holds the registered widgets; `RightSidebarSlot` in the code) and finds the in-context discussions panel on units that have discussions enabled, as on `master`. The discussions widget is the one registered widget, hard-coded; the framework's handling of several registered widgets (one trigger each, one panel open) ports intact so later widgets slot in. The auxiliary sidebar stubs from #2196 are replaced. Two things wait for the Slot API in #2185 and are looked at again when tabs become widgets in #2186: how a site registers widgets (the `SIDEBAR_WIDGETS` list on `master`; under frontend-base plausibly the slot itself, with a Tutor plugin such as tutor-forum inserting the discussions widget), and the upgrade widget, whose panel is a plugin slot with no default content (since [14c662dc](https://github.com/openedx/frontend-app-learning/commit/14c662dc530c1982d016a2ffd2ffe2af51603303)) and whose default registration #1902 already lists for removal.

## What moves

Files port from the legacy `src/` tree to the same relative path under `frontend-base/src/`, with their tests, and get a line each in `frontend-base/manifest.tsv`.

- The auxiliary sidebar and its trigger: the generic sidebar and trigger shells the framework from #2197 already holds, now rendered through the auxiliary sidebar slot and its trigger slot (`RightSidebarSlot` and `RightSidebarTriggerSlot`, keeping their names), which become placeholder slots with those shells as their default content.
- The widget registry ([`defaultWidgets.js`](https://github.com/openedx/frontend-app-learning/blob/master/src/courseware/course/sidebar/defaultWidgets.js)), un-stubbed from #2197 with the discussions widget as its one entry: each widget is a sidebar, a trigger, a provider and an availability check, sorted by priority. The `SIDEBAR_WIDGETS` config read and the upgrade widget's entry stay out until #2185.
- The discussions widget ([`src/widgets/discussions/`](https://github.com/openedx/frontend-app-learning/tree/master/src/widgets/discussions)): available on a unit with in-context discussions enabled; its sidebar embeds the discussions app for the unit's topic. Its URL comes from the discussions role, resolved through frontend-base's route resolver (an external route a site supplies today, the installed discussions app later), in place of `DISCUSSIONS_MFE_BASE_URL`.

## Testing

The tests of the files that move here, the discussions widget's and the auxiliary sidebar slots', port with them, as do the framework's mock-widget suites (`SidebarTriggers.test.jsx`, `defaultWidgets.test.js`) that register two or more widgets, and reach the page through the exported route array at a unit URL, with the unit, course metadata and discussions-topic queries mocked per the conventions #2189 set.

## Acceptance

- [ ] The auxiliary sidebar opens and closes from its trigger; on a unit with in-context discussions enabled the discussions panel loads the discussions app for that unit
- [ ] With a second widget registered in a test, each available widget has its own trigger, clicking one opens its panel and closes the other, and priority ordering holds (the framework's mock-widget suites)
- [ ] The auxiliary sidebar slot and its trigger slot are placeholder slots rendering their default content
- [ ] Types, lint and tests of the new package pass; the legacy workflow stays green; `npm run dev` from the package serves courseware with the discussions widget
- [ ] Manifest lines added for every file moved; the discussions widget directory's coverage compared against the `master` baseline
