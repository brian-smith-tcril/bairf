Part of #1905. Depends on #2197.

**Goal:** a learner in courseware on a frontend-base site opens the auxiliary sidebar (the panel beside the content that holds the registered widgets; `right_sidebar` in the slot ids) and finds the two built-in widgets as on `master`: the in-context discussions panel on units that have discussions enabled, and the upgrade panel on a course with a verified mode. Operators can still add their own widgets and disable the built-in ones. The auxiliary sidebar stubs from #2196 are replaced.

## What moves

Files port from the legacy `src/` tree to the same relative path under `frontend-base/src/`, with their tests, and get a line each in `frontend-base/manifest.tsv`.

- The auxiliary sidebar and its trigger: the generic sidebar and trigger shells the framework from #2197 already holds, now rendered through the auxiliary sidebar slot and its trigger slot (`right_sidebar` and `right_sidebar_trigger`, which keep their ids), which become placeholder slots with those shells as their default content.
- The widget registry's two built-in entries ([`defaultWidgets.js`](https://github.com/openedx/frontend-app-learning/blob/master/src/courseware/course/sidebar/defaultWidgets.js)), un-stubbed from #2197: each widget is a sidebar, a trigger, a provider and an availability check, sorted by priority.
- The discussions widget ([`src/widgets/discussions/`](https://github.com/openedx/frontend-app-learning/tree/master/src/widgets/discussions)): available on a unit with in-context discussions enabled; its sidebar embeds the discussions app for the unit's topic. Its URL comes from the discussions role, resolved through frontend-base's route resolver (an external route a site supplies today, the installed discussions app later), in place of `DISCUSSIONS_MFE_BASE_URL`.
- The upgrade widget ([`src/widgets/upgrade/`](https://github.com/openedx/frontend-app-learning/tree/master/src/widgets/upgrade)): available when the course has a verified mode; its panel, trigger, context and utilities. Its own plugin slot inside the panel becomes a placeholder slot, with the six props it passed, including the two aliases Learning's ADR 0010 deprecated, recorded for the Slot API port in #2185.

## Operator configuration

On `master` operators add external widgets and disable built-in ones through a `SIDEBAR_WIDGETS` list read from the runtime config, documented in the upgrade widget's README. Under frontend-base that list is read from Learning's app config under the same key; the shape of each entry is unchanged, since app config is JavaScript as the legacy plugin config file was. The README is updated to say where the list now lives. The location change is an operator-facing change and is noted as such; it is not a change to what can be configured.

## Testing

The tests of the files that move here, the two widgets' and the auxiliary sidebar slots', port with them and reach the page through the exported route array at a unit URL, with the unit, course metadata and discussions-topic queries mocked per the conventions #2189 set.

## Acceptance

- [ ] The auxiliary sidebar opens and closes from its trigger; on a unit with in-context discussions enabled the discussions panel loads the discussions app for that unit; on a course with a verified mode the upgrade panel shows
- [ ] A widget entry in app config adds an external widget; an entry with `enabled: false` removes a built-in one; priority ordering holds
- [ ] The auxiliary sidebar slot, its trigger slot and the upgrade panel's slot are placeholder slots rendering their default content
- [ ] The upgrade widget README names the app-config location of the widget list
- [ ] Types, lint and tests of the new package pass; the legacy workflow stays green; `npm run dev` from the package serves courseware with both widgets
- [ ] Manifest lines added for every file moved; the widgets directory's coverage compared against the `master` baseline
