**Goal:** every courseware URL form resolves under frontend-base to the course, sequence and unit it resolves to on `master`, shown on a stub in place of the course page. The courseware container, its redirects and the courseware data module port; the course component itself, with sequence, unit, sidebars and everything inside, is stubbed to print the three resolved ids and is replaced by the next courseware issue. The courseware stub from #2188 is replaced.

**Why a stub:** the redirect rules are a page of their own, and testing them needs nothing below them. Landing them first means the sequence-and-unit issue inherits a container whose every URL form is already verified.

## What moves

Files port from the legacy `src/` tree to the same relative path under `frontend-base/src/`, with their tests, and get a line each in `frontend-base/manifest.tsv`.

- The courseware container ([`CoursewareContainer.tsx`](https://github.com/openedx/frontend-app-learning/blob/master/src/courseware/CoursewareContainer.tsx)): it renders the redirects, then the tab-page frame with the courseware tab active and the courseware metadata query beside the course-metadata one, and inside it the course component. The sequence-position save and block-completion handlers it owns port with it.
- The redirects ([`CoursewareRedirects.tsx`](https://github.com/openedx/frontend-app-learning/blob/master/src/courseware/CoursewareRedirects.tsx)), which implement the liberal path handling of Learning's [ADR 0008](https://github.com/openedx/frontend-app-learning/blob/master/docs/decisions/0008-liberal-courseware-path-handling.md): every courseware path converges on `course/:courseId/:sequenceId/:unitId`.
- The courseware data module: courseware metadata, sequence metadata, the minimal course outline, resume block and parent-sequence lookups, their keys, API functions and normalizers.
- The two route wrappers from `master`'s app root, as layout routes around Learning's course routes in the route tree from #2188: the URL-decoding wrapper, which decodes course and block keys in the path and redirects to the decoded URL, and the path-fixes wrapper, which turns spaces in the path into plus signs and redirects. Both port with their behavior unchanged, as do the courseware redirects. frontend-base's route-loader precedent ([`authenticatedLoader`](https://github.com/openedx/frontend-base/blob/main/runtime/routing/authenticatedLoader.ts), and the shell's home redirect in [`getAppRoutes`](https://github.com/openedx/frontend-base/blob/main/shell/router/getAppRoutes.ts)) is for decisions made from synchronous state before render; Learning's redirects need server data (the resume block, sequence metadata and its error state, the outline), which is the case frontend-app-instructor-dashboard also handles with a component rendering `Navigate` ([`routes.tsx`](https://github.com/openedx/frontend-app-instructor-dashboard/blob/main/src/routes.tsx)). Whether any of them becomes a loader is a later question. The `preview/course/...` patterns are already on the courseware route.

## The stub

The course component is replaced by a stub that prints the course, sequence and unit ids the container resolved, inside the tab-page frame. It exists only in this issue and is deleted by the sequence-and-unit issue.

## The redirect table to verify

From the redirect rules on `master`, each form and its destination:

| Form | Destination |
|---|---|
| `course/:courseId` | the learner's resume unit; else the course's first sequence |
| `course/:courseId/:sequenceId` | the sequence's active unit |
| `course/:courseId/:sequenceId/first`, `/last` | that sequence's first or last unit |
| `course/:courseId/:sectionId[/:unitId]` | the section's first sequence, or the unit's own sequence, per ADR 0008 forms 2 and 3 |
| `course/:courseId/:sequenceId/:unitId` with an empty sequence | the sequence URL without a unit |
| `preview/course/...` as a non-staff user | the same path without `preview` |
| any form when the outline fails to load but access is granted | the course home |
| any form when access is denied | the tab-page frame's access handling, as on every tab |
| a path with an encoded course key or spaces | the decoded, plus-signed path |

## Testing

The redirect and container tests port with their files and reach the container through the exported route array at each form above; the stub's ids are what the tests assert. Mocks follow the conventions #2189 set.
