Part of #1905. Depends on #2191.

**Goal:** every courseware URL form resolves under frontend-base to the course, sequence and unit it resolves to on `master`, shown on a stub in place of the course page. The courseware container, its redirects, the rest of the courseware data module and the two route wrappers from `master`'s app root port; the course component itself, with sequence, unit, sidebars and everything inside, is stubbed to print the three resolved ids and is replaced by #2196. The courseware stub from #2188 is replaced.

**Why a stub:** the redirect rules are a page of their own, and testing them needs nothing below them. Landing them first means the sequence-and-unit issue inherits a container whose every URL form is already verified.

**What differs from `master`:** the URL-decoding wrapper decodes every segment of the path where `master` decodes only the route params, so an escaped character in a fixed word such as `course` is cleaned up too, and a course URL with a trailing slash stays as typed. The wrapper also brings back the page event, which the three tabs ported so far do not send.

## What changes in the moved code

- Imports: every `@edx/frontend-platform*` import becomes one from `@openedx/frontend-base`; `getConfig().LMS_BASE_URL` becomes `getSiteConfig().lmsBaseUrl`. The non-null assertions `master`'s files carry port as they are; the port adds none.
- **Every query spreads `queryDefaults`**, as each ported query has since #2189. `sequenceMetadataQuery` keeps its own `retry: false` after the spread.
- **Redirect destinations resolve Learning's roles**, the rule #2190 set for Learning's links to its own pages. `coursewarePath` stays the one function the rules call. Its course form is the courseware role's URL, its sequence form is `getSequenceUrl`, and its unit form is a function added beside `getSequenceUrl` in `courseware/urls.ts`, which arrives here with its first caller. The preview forms are the learning role's URL followed by `/preview/course/<ids>`, the prefix `TabPage` already builds for its access-denied redirect. The outline-failure rule resolves `courseOutlineRole` with the course id directly, without the tab-list gate of `useCourseOutlineUrl`, since `master` redirects there whatever `tabs` holds. The non-staff preview rule's `pathname.replace('/preview', '')` is unchanged: it removes the same segment from `/learning/preview/course/…`.
- **`useIsPreview`** compares the pathname with the learning role's URL followed by `/preview`; `startsWith('/preview')` is never true under `/learning`.
- **The wrappers become layout routes.** `PathFixesProvider` is the element of a pathless layout route holding all of the `learning` route's children, since `master` wraps every route with it, the three non-course routes included. `DecodePageRoute` is the element of the `course/:courseId` and `preview/course/:courseId` parents, which render a bare `<Outlet />` today, and keeps `PageWrap`, now frontend-base's; that restores the page event on every course route, the three ported tabs included.
- **`DecodePageRoute` decodes every path segment and reads no route list.** Its body becomes: split `location.pathname` on `/`, pass each segment through `decodeUrl` (`master`'s helper, unchanged), rejoin, and render `<Navigate replace>` to the result when it differs. `master` finds the params by matching `location.pathname` against `DECODE_ROUTES`, the list its router is also built from. The package's router is built from the tree in `routes.tsx`, so a port has to change how the params are found either way, and decoding each segment needs no stand-in for the list.
  - Weighed and not taken: `DECODE_ROUTES` ported into `constants.ts` and matched behind the learning role's URL (two definitions of the course routes, where `master` has one); the patterns built in `routes.tsx` from the two parents' `children` and passed to the wrapper as a prop (`master`'s algorithm kept, at the cost of a prop, a helper and a coupling to the tree's shape, to preserve a params-only decode with no recorded purpose, below).
  - Why the wrapper cannot simply read the router's params: `matchPath` returns them raw (it only turns `%2F` into `/`), where the router's own matching runs `decodePath` first, so `useParams()` in a layout route returns them already decoded once; `generatePath` takes the pattern as its first argument and does not encode; `useMatches()` carries each match's `id`, `pathname`, `params` and `handle`, and no pattern.
  - The history of decoding only the params, read from #1090, its one commit, #1128 and #2047. The wrapper was written for react-router 5 as a drop-in for frontend-platform's `PageRoute`: `<Switch>` hands each route a `computedMatch` of `{ url, path, params }`, so the params were already in hand, and the body decoded them and called `generatePath(path, params)`. The only reason recorded is the comment added with it, still on `master`: "only decode params not the entire url. it is just to be safe and less prone to errors". #1090 has no inline review threads; one approval reads "We may want a non-rewriting-path option in the future if this winds up being over-zealous, but for now it seems a reasonable enough solution to avoid having to do larger overrides to the PageRoute component logic", the other "This is a risky change". No failure that decoding a fixed segment would cause is named. `DECODE_ROUTES` did not exist then: #1128 (react-router 6, 2023) added it because v6 has no `computedMatch`. The wrapper exists in no other repository of the `openedx` or `edx` organizations (code search for `DecodePageRoute`, 2026-11-12). The params-only rule protects nothing in a param position: `master` already turns `%2F` in a param into `/` and `%3F` into `?` before `generatePath`, which does not encode, and decoding each segment does the same.
  - What `master`'s tests hold about fixed segments. `decodeRoutes.test.tsx` (#2047: 13 route templates against 10 course-key spellings, plus 4 rows) puts every encoding in a course key, sequence, unit or discussion topic position and none in a fixed segment. `index.test.jsx`'s "should only decode the url params and not the entire url" (#1090) is the one case about a fixed segment: its fixture route is `/course/:courseId/some%2Bthing/:unitId`, supplied by mocking `../constants`, and it asserts `some%2Bthing` stays encoded in the redirect. Decoding every segment fails it. #2047's commit message says of that fixture: "a route pattern whose literal is spelled with a percent-escape can no longer match anything", react-router having decoded the pathname before matching since 6.20, which is why the case mounts the wrapper on a catch-all. No route of Learning's has such a segment.
  - Two differences from `master` follow, both read in react-router 6.30.6 (`@remix-run/router` 1.23.4), pinned by this issue's tests and named in the wrappers' PR. A course URL with a trailing slash is no longer redirected to the form without it: on `master` that is a side effect (`compilePath`'s matcher takes trailing slashes into the matched `pathname`, `generatePath` drops empty segments, and the two differ), and the page renders at either form. A percent-escape in a fixed word of the path (`learning`, `course`, `preview`) is decoded and redirected, where `master`'s patterns do not match such a path and leave the address as typed; the page renders either way, since the router decodes before matching.
- **Routes.** The three courseware routes and two preview routes render the container through `lazy`, loading `./courseware` with the `learning-courseware` chunk name; the `courseware` stub page goes. Their ids and roles stay. The preview index keeps its 404 loader.
- Restored where this issue's URL marks them: the two names in `courseware/data/index.js`, the two factory imports, the two `courseBlocks.factory.js` builders, the comment in `course-exit/utils.test.ts`, and `useMinimalCourseOutline`, which becomes the real query.
- Console and lint: the package's suite fails on any console output, so a warning a ported file raises is fixed in the file and listed in its PR; a lint finding the port surfaces is fixed where that changes no behavior, and `eslint-disable` comments go where the package's lint lacks the rule or no longer reports it.

## The redirect table to verify

From the eight rules on `master`. Paths are under `/learning`; each row is where the path settles, since one rule's destination can be a form another rule then moves.

| Form | Settles on |
|---|---|
| `course/:courseId` | the learner's resume unit; else the active unit of the course's first sequence |
| `course/:courseId/:sequenceId` | the sequence's active unit |
| `course/:courseId/:sequenceId/first`, `/last` | that sequence's first or last unit |
| `course/:courseId/:sectionId` | the active unit of the section's first sequence (ADR 0008 form 2) |
| `course/:courseId/:sectionId/:unitId` | the unit under its own sequence (form 3) |
| `course/:courseId/:unitId` | the unit under its parent sequence; the course root's destination when the lookup finds none (form 5) |
| `course/:courseId/<an id that is no sequence, section or unit>` | the course root's destination |
| `course/:courseId/:sequenceId/:unitId` with an empty sequence | the sequence URL without a unit |
| `preview/course/…` as a staff user | the same rules, with every sequence and unit destination under `preview` |
| `preview/course/…` as a non-staff user | the same path without `preview` |
| any form when the outline fails to load but access is granted | the course home |
| any form when access is denied | the tab-page frame's access handling, as on every tab |
| a path with an encoded course key, sequence or unit, or with spaces | the decoded, plus-signed path |
