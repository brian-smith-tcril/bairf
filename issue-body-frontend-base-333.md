An app's stylesheet stays in the page after a learner navigates to another app, so its rules apply to every app the site composes from then on. The converted apps handle this in different ways, several of which leave rules applying site-wide, and the docs do not say how an app should scope its selectors. Found while porting Learning to frontend-base (openedx/frontend-app-learning#1905).

## How an app's styles reach the page

- The migration guide's [Runtime styles](https://github.com/openedx/frontend-base/blob/ae5ec935e53e084ba6f3be0521ecb1cec274810f/docs/how_tos/migrate-frontend-app.md#runtime-styles) are "imported from the app's component code ... and loaded automatically whenever the app's code runs (including as a lazy-loaded route in a larger site)".
- [`getStylesheetRule.ts`](https://github.com/openedx/frontend-base/blob/ae5ec935e53e084ba6f3be0521ecb1cec274810f/tools/webpack/common-config/all/getStylesheetRule.ts#L84-L91) keeps app styles in the JS bundles in dev (`style-loader`) and extracts them to CSS files in production (`MiniCssExtractPlugin`). Either way, nothing removes them when the app's routes unmount.
- openedx/frontend-app-account found the consequence: [`b3476d4`](https://github.com/openedx/frontend-app-account/commit/b3476d418b6b00c9aa3ccb8af42dd107d88adde5), "In the shell the app stays loaded across soft navigations, so its stylesheet must not restyle other apps".
- Cascade layers order precedence; they do not scope. Every stylesheet is wrapped in a layer (`paragon, shell, app, site, brand`, per the [theming guide](https://github.com/openedx/frontend-base/blob/ae5ec935e53e084ba6f3be0521ecb1cec274810f/docs/how_tos/theming.md#css-ownership)), and an app's rule still applies to any element its selector matches.
- The shell's page has one `<div id="root">` for the whole site ([`shell/public/index.html`](https://github.com/openedx/frontend-base/blob/ae5ec935e53e084ba6f3be0521ecb1cec274810f/shell/public/index.html#L9), mounted in [`shell/site.tsx`](https://github.com/openedx/frontend-base/blob/ae5ec935e53e084ba6f3be0521ecb1cec274810f/shell/site.tsx#L36)). Before conversion, `#root` was each app's own root, and learner-dashboard's and Learning's stylesheets used it as their scope.

## What the docs say

- The theming guide's [CSS ownership](https://github.com/openedx/frontend-base/blob/ae5ec935e53e084ba6f3be0521ecb1cec274810f/docs/how_tos/theming.md#css-ownership): "These styles must contain only app-scoped rules: they must not re-bundle shell or Paragon base styles, and they must not import brand packages at runtime."
- "App-scoped" is defined there by what the stylesheet must not bundle. Neither guide says how an app keeps its selectors from matching other apps' markup.

## Why app-specific names are not enough

A site operator can compose apps from outside the `openedx` org, so a class name unique among Open edX's apps (`.page__account-settings`, `.dates-day`) can still collide with one in another app on the same site, in either direction.

## Questions

- What should "app-scoped" mean for an app's selectors, and how should an app achieve it?
- Does that belong to each app, or to the shell or build?
- How should third-party stylesheets an app imports, such as Font Awesome 4, be handled?
- Once defined, how do the converted apps get brought in line?
