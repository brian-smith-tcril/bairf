## How it happens today

- An app sets its document title with `<Helmet>` from `react-helmet`: [ADR 0015](https://github.com/openedx/frontend-base/blob/72d70535cf77e98be8f859aa5746c3dddb4d02d2/docs/decisions/0015-page-titles-via-helmet.rst#L38-L62) (status Proposed) says "Every route-level page component in an app is responsible for setting the document title. Apps do this with `<Helmet>` from `react-helmet`", each app declaring the dependency, and the migration guide's [Set the document title on every route-level page](https://github.com/openedx/frontend-base/blob/72d70535cf77e98be8f859aa5746c3dddb4d02d2/docs/how_tos/migrate-frontend-app.md#set-the-document-title-on-every-route-level-page) gives the code.
- `react-helmet` 6.1.0 builds `Helmet` on `react-side-effect`: [`withSideEffect(…)(NullComponent)`](https://github.com/nfl/react-helmet/blob/6.1.0/src/Helmet.js#L285-L291). `react-side-effect` 2.1.2 wraps it in a class component named `SideEffect(NullComponent)` that defines [`UNSAFE_componentWillMount`](https://github.com/gaearon/react-side-effect/blob/v2.1.2/src/index.js#L48-L70).
- The shell renders the site inside [`<StrictMode>`](https://github.com/openedx/frontend-base/blob/72d70535cf77e98be8f859aa5746c3dddb4d02d2/shell/site.tsx#L38-L47).
- Observed on a development site running Learning's frontend-base package (`@openedx/frontend-base` 2.0.0-alpha.17, React 18.3.1, `react-helmet` 6.1.0), in the browser console on loading a page:

  ```
  Warning: Using UNSAFE_componentWillMount in strict mode is not recommended and may indicate bugs in your code. See https://reactjs.org/link/unsafe-component-lifecycles for details.

  * Move code with side effects to componentDidMount, and set initial state in the constructor.

  Please update the following components: SideEffect(NullComponent)
  ```
- `react-helmet`'s latest release on npm is 6.1.0, published 2020-06-08.

## What the docs say

- React's [`<StrictMode>` reference, Fixing deprecation warnings enabled by Strict Mode](https://react.dev/reference/react/StrictMode#fixing-deprecation-warnings-enabled-by-strict-mode): "React warns if some component anywhere inside a `<StrictMode>` tree uses one of these deprecated APIs: `UNSAFE_` class lifecycle methods like `UNSAFE_componentWillMount`."
- [ADR 0015, Rejected alternatives, Standardizing on `react-helmet-async`](https://github.com/openedx/frontend-base/blob/72d70535cf77e98be8f859aa5746c3dddb4d02d2/docs/decisions/0015-page-titles-via-helmet.rst#L111-L121): "`react-helmet-async` is generally recommended over `react-helmet` for React 18+ projects: it avoids `act()` warnings, supports streaming SSR, and is actively maintained." and "Standardizing on `react-helmet-async` across all apps is a worthwhile follow-up but does not need to block this decision". The ADR does not mention this warning.
- The [React 19 release post, Support for Document Metadata](https://react.dev/blog/2024/12/05/react-19#support-for-metadata-tags): "In the past, these elements would need to be inserted manually in an effect, or by libraries like `react-helmet`" and "In React 19, we're adding support for rendering document metadata tags in components natively".
- The [`react-helmet-async` README](https://github.com/staylor/react-helmet-async/blob/main/README.md#react-19) (3.1.0 on npm, peer `react` 16.6 to 19): "This package is a fork of React Helmet.", and under React 19, "Starting with version 3.0.0, this package detects the React version at runtime" and "you may not need this package at all — React 19's built-in metadata handling may be sufficient."

## How it got here

- The ADR and the migration guide's section came in with #252 (merged 2026-04-29). The ADR takes the pattern from openedx/frontend-app-authn, which already set titles with `react-helmet` ([`src/login/LoginPage.jsx`](https://github.com/openedx/frontend-app-authn/blob/5687d65baf679f977d7439f694a56dda7f0a6a5d/src/login/LoginPage.jsx#L9)).

## Where it bites

- Learning renders `Helmet` in [`src/Main.tsx`](https://github.com/openedx/frontend-app-learning/blob/c78935cc73aa5bbc7fc57e75b8f3849431834e3b/frontend-base/src/Main.tsx#L2) and [`src/tab-page/LoadedTabPage.tsx`](https://github.com/openedx/frontend-app-learning/blob/c78935cc73aa5bbc7fc57e75b8f3849431834e3b/frontend-base/src/tab-page/LoadedTabPage.tsx#L2) of its frontend-base package, which is where the warning above was seen.
- The same component is rendered by the route entries of the other converted apps, which were not run for this issue: [account](https://github.com/openedx/frontend-app-account/blob/87dcc393142b0a8882bb17706458d9a1a1763417/src/Main.tsx#L3), [profile](https://github.com/openedx/frontend-app-profile/blob/c4ff88501d36a60fef8761b0a2dfcee07ba1dd09/src/Main.tsx#L2), [learner dashboard](https://github.com/openedx/frontend-app-learner-dashboard/blob/a943af914a4cd5c7617cddd1d6e29d4ba8ffbb3c/src/Main.jsx#L2), [instructor dashboard](https://github.com/openedx/frontend-app-instructor-dashboard/blob/60c03ad3510c4c692d2528e46b024c4c30d36b6d/src/Main.tsx#L2), [admin console](https://github.com/openedx/frontend-app-admin-console/blob/ab1b4bb6b1442dd551f67a7cce3a65bd8c4f8274/src/Main.tsx#L2), [gradebook](https://github.com/openedx/frontend-app-gradebook/blob/f57f7adef252f0c779315f66abb402d383ccf483/src/Main.tsx#L2), and catalog's [home](https://github.com/openedx/frontend-app-catalog/blob/586f5f6d7f76f92dfc4f0014cafc7f318d9914ab/src/home/HomePage.tsx#L1), [catalog](https://github.com/openedx/frontend-app-catalog/blob/586f5f6d7f76f92dfc4f0014cafc7f318d9914ab/src/catalog/CatalogPage.tsx#L2) and [course about](https://github.com/openedx/frontend-app-catalog/blob/586f5f6d7f76f92dfc4f0014cafc7f318d9914ab/src/course-about/CourseAboutPage.tsx#L2) pages.
- A test that renders under `StrictMode` prints it too: mounting `Helmet` inside `<StrictMode>` in jsdom, with React 18.3.1, writes the same warning to `console.error`, and mounting it outside `<StrictMode>` writes nothing.
- In the development console it sits among the app's own warnings on every page load.
