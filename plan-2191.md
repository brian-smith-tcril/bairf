# Plan: openedx/frontend-app-learning#2191 — port the outline tab

Draft, written 2026-11-12, not posted. Once the open questions below are answered this becomes the plan block of the issue body, mirrored in `issue-body-outline-tab.md`; the effort decision numbers are kept here and restated in words there.

## Open, for Brian

1. **The handouts stylesheet.** `LmsHtmlFragment.jsx` links `<BASE_URL>/static/LmsHtmlFragment.css`, a file `master`'s `webpack.prod.config.js` copies out of `public/static/`. The package is a library a site bundles and has no directory served at the site's base URL; frontend-base's migration how-to says nothing about static files. Proposed: the file's three rules go inline in the iframe document as a `<style>` element (What changes).
2. **Where the flag SVGs live.** The `<img>` form is frontend-base's own guidance (settled, below). The package's `build` target copies only `*.scss` files and files under an `assets/` directory into `dist/`, so the three SVGs have to sit under one to ship. Proposed: `widgets/flag_*.svg` ports to `widgets/assets/flag_*.svg`, the how-to's convention, with the manifest carrying the move.

## Settled with Brian, 2026-11-12

- **Two layers** on the running stack, shared modules then the tab (Layers).
- **The dates links read `useDatesTabUrl()`** (What changes). The first statement of the difference from `master`, "today the link always renders", was wrong and is corrected there: the two cases are a hidden Dates tab and a learner gated by the entrance exam. The `master` behavior has its own issue, openedx/frontend-app-learning#2250 (mirror `issue-body-2250.md`, `settled` in `UPSTREAM.md`), with no status line yet: "#2191 fixes this" is premature before the port exists (Brian). The line is added to that issue's body once the outline layer's PR is open, as #2243 got its line after #2249 was.
- **The flags render as images.** Not a choice: frontend-base's migration how-to, section "SVGR "ReactComponent" imports have been removed" (`docs/how_tos/migrate-frontend-app.md` at `72d70535`), says: "We have removed the `@svgr/webpack` loader because it was incompatible with more modern tooling (it requires Babel). [...] Please replace that export with the default URL export and set the URL as the source of an `<img>` tag, rather than using `ReactComponent`." It names frontend-app-learning as one of the apps that use the export.

## What changes in the moved code

- Imports: every `@edx/frontend-platform*` import becomes one from `@openedx/frontend-base`; `getConfig()` reads become the site-config field or `getAppConfig(appId)` per the key list above.
- **Sequence titles link through `getSequenceUrl` (decision 38).** On `master` `SequenceTitle.tsx` renders `<Link to={`/course/${courseId}/${id}`}>`, a path at the root of Learning's own site, when the block carries an `lms_web_url` (`showLink` in `courseHomeOutline.ts`, which the outline serializer nulls when links are disabled). Under the shell Learning's routes sit below `/learning`, so the `to` becomes `getSequenceUrl(courseId, id)`; the element stays react-router's `Link` and `showLink` stays the gate. Until #2195 the link lands on the courseware stub.
- **The dates links resolve the dates role (decision 38).** `CourseDates.jsx` renders an anchor and `ScheduledCotentAlert.jsx` a `Button`, both to the response's `datesTabLink`, which the outline view builds as `get_learning_mfe_home_url(course_key, url_fragment='dates')` (`lms/djangoapps/course_home_api/outline/views.py` in openedx/openedx-platform): Learning's dates tab, reached by a full page load. Here both read `useDatesTabUrl()` and render through `getLinkProps`, so the switch stays in the client; the alert's payload carries the hook's URL where it carried the response's. The hook returns nothing when the course metadata's `tabs` has no dates tab, and then neither renders. `tabs` lacks the dates tab in two cases (`get_course_tab_list` in `lms/djangoapps/courseware/tabs.py`): the Dates tab is hidden, where on `master` the widget is already empty (the outline view empties its date blocks when `DatesTab.is_enabled` is false) but the alert's button still shows and opens a dates page with no dates; and a learner who must complete the entrance exam, for whom only the courseware tab is listed, where on `master` both the link and the button show and the dates page lists the dates. `master`'s course exit page already gates its schedule button on `useDatesTabUrl()` (`CourseInProgress.jsx`).
- **The certificate alert's grades button.** `CertificateStatusAlert.jsx` already reads `useProgressTabUrl()`, which resolves the progress role since #2190. Its `Button` takes `getLinkProps(buttonLink)` when the link is that URL, so it opens the progress tab in the client; the other three buttons (the certificate web view, the request, ID verification support) keep `href`, since they leave Learning or have no link.
- **Links left as the response gives them.** The start or resume button (`resume_course.url`: a `jump_to` URL for the last completed block, or the course block's `lms_web_url`, which only openedx-platform's `jump_to` view can turn into a sequence and unit), the course tools (the URLs the response's `course_tools` carries), the date summary's assignment and upgrade links (as the dates tab's are since #2189), the proctoring onboarding link. Each stays a plain `href`.
- **The handouts stylesheet goes inline (open question 1).** `LmsHtmlFragment.jsx` builds the iframe's document as a string. The `<link>` to `<BASE_URL>/static/LmsHtmlFragment.css` becomes a `<style>` element holding the file's three rules as they are (link colour, the `inline-link` underline, the `small` font size). The `lms-main.css` link beside it keeps its form, with the theme name read from the app config.
- **The goal card's flags render as images.** `master`'s `LearningGoalButton.jsx` imports each SVG's `ReactComponent`, which frontend-build's `@svgr/webpack` rule provides and frontend-base's webpack does not (its how-to, quoted above). Here it imports the three SVGs' URLs and passes `<img src={url} alt="" />` as `buttonIcon`; `FlagButton`'s prop type is an element either way, and each SVG carries its own size and fills. The files' content is unchanged; their directory is open question 2.
- **The goal card clears `weekly_goal` through the router.** On `master` `WeeklyLearningGoalCard.jsx` calls `history.replace({ search })` on frontend-platform's `history`, a `createBrowserHistory` instance of its own beside the `BrowserRouter` `AppProvider` mounts, so the address bar changes and the router's location does not. frontend-base exports no `history`. Here the effect calls react-router's `navigate({ search }, { replace: true })`, as the tab's own `start_course` effect does with `navigate`; the router's location then changes, the effect runs once more and finds no `weekly_goal`. The goal is saved once either way.
- Placeholder slots: `CourseHomeSectionOutlineSlot` keeps its file and name and renders its default content, the `<ol>` of sections, in a bare fragment; `CourseOutlineTabNotificationsSlot` has no default content and renders nothing. Neither imports the plugin framework. The props they passed to plugins (`expandAll`, `sectionIds`, `sections`; `courseId`, `model: 'outline'`) are recorded in the manifest line's commit for #2185.
- Routes: the `home` route object becomes `lazy`, loading `./course-home/outline-tab` with the `learning-outline` chunk name; its id and role stay. Its page-rule assertion moves from `routes.test.tsx` to the outline test.
- Styles: `style.scss` gains `@use` lines for `DateSummary.scss`, `FlagButton.scss` and `ProctoringInfoPanel.scss` (all three use only Paragon variables and their own), and the one rule of `master`'s `src/index.scss` that styles this tab and sits in no partial, copied as it is: the `.course-outline-tab .pgn__card` header rule under the extra-small breakpoint. The `import './DateSummary.scss'` and `import './FlagButton.scss'` lines in the two components go, since the package's only stylesheet import is `Main.tsx`'s.
- Console: the package's suite fails on any console output, so each warning the outline components raise is fixed in the component. Known from reading: `DateSummary`, `LmsHtmlFragment`, `WeeklyLearningGoalCard` and `EffortEstimate` set `defaultProps` on a function component. Each loses them; `LmsHtmlFragment` writes `className` into the document's `<body class>`, where an absent one would read `undefined`, so it takes a default parameter. react-bootstrap's `findDOMNode` warning, which the inventory attributes to this suite, is already silenced by pattern under openedx/paragon#4523. The inventory's `Unexpected course block type` log lines are read with the suite running; the normalizer handles `course`, `chapter` and `sequential`, so the block that raises it is in a factory. Anything else the failing hook finds is fixed the same way and listed in the PR.
- Lint: messages without a `description` gain one, ids and default messages untouched; `eslint-disable` comments go where the package's lint lacks the rule or no longer reports it; the autofixer's whitespace.
