# Plan: #1977 — dissolve the model-store normalized cache (layer F, the teardown)

The last layer of the model-store dissolution. Layers A–E are landed or on the
running stack #2141 (A #2083 … D4 #2089, E #1999 as PR #2153), so this layer
stacks above `bsmith/access-expiration-banner-query-read`. Closes #1977 and
#1978: once `models` is gone, `store.ts` holds only the external `specialExams`
reducer, which is #1978's stated endpoint. The decomposition plan this file
previously held (eleven layers, D1–D5) is embedded verbatim in the #1977 issue
body. Planned 2026-10-02 against the code as layer E left it.

## How it works today (after layer E)

**Nothing reads the model store any more.** On the current branch, non-test
source has:

| What | Count | Where |
|---|---|---|
| `useModel` / `useModels` readers | 0 | the only match is the bridge's own comment |
| `state.models` selectors | 0 | `courseware/data/modelReader.ts` went in #2089 |
| query `meta` entries the bridge consumes (`modelType`, `models: [...]`) | 0 | the three tab-data hooks dropped theirs in #2153 |
| explicit `dispatch(addModel / updateModel / …)` writers | 0 | moved to `setQueryData` in #2122–#2140 |
| `react-redux` imports | 1 | `generic/model-store/hooks.js`, the deleted module itself |
| `from 'redux'` imports | 2 | `data/modelStoreBridge.ts`, `queryClient.ts` (the `Store` type) |

The #2153 PR body says it: "no query opts into the bridge any more and #1977
becomes deletion only."

**What still holds the store up:**

- `src/store.ts` registers `models: modelsReducer` beside `specialExams`, and
  exports a `RootState` type with **zero importers**.
- `src/queryClient.ts` wires `bridgeToModelStore` as the app `QueryCache`'s
  `onSuccess`, takes a `store: Store` parameter on `createAppQueryCache` and
  `createQueryClient` only to feed it, and widens `Register.queryMeta` with
  `ModelStoreMeta`. `src/index.jsx` calls `createQueryClient(store)`.
- `src/generic/model-store/` — `slice.js` (80 lines), `hooks.js` (20),
  `index.js` (16), `hooks.test.tsx` (43). `src/data/modelStoreBridge.ts` and
  its test (139 lines).
- `src/setupTest.js` imports the slice's actions and reducer; `initializeTestStore`
  builds a two-reducer store, mocks the course endpoints, then **seeds the
  models** through `seedCoursewareModels` (fetches the three course payloads
  through the mock and dispatches `coursewareMeta`, `courseHomeMeta`, `sections`,
  `sequences`) and `seedSequenceModels` (`sequences`, `units`), unless the
  caller passes `excludeFetchCourse` / `excludeFetchSequence`. `getTestStoreIds(store)`
  reads the course and sequence ids back out of the seeded `models` keys.
  `createTestQueryClient(store)` installs the app `QueryCache` (and so the
  bridge) when given a store, a bare one otherwise.
- Tests that touch the above: **41** call `initializeTestStore` (25 use the
  returned store, 15 only `await` it); **24** call `getTestStoreIds`; **18**
  pass `excludeFetchCourse` / `excludeFetchSequence` (two of them as `false`);
  **20** pass a store to `createTestQueryClient`; **44** `render(…, { store })`
  options in 11 files hand the store back to `setupTest`'s wrapper; **29**
  calls in 6 files build a *second* store with `overrideStore = false` so a
  per-test fixture set does not replace the suite's `globalStore`;
  `CourseExit.test.jsx` fetches two payloads and dispatches `addModel` by
  hand before every render; `queryClient.test.ts` builds four models-only
  stores and has one test for the bridge.
- **No test touches the store for anything else.** Outside the deleted
  bridge and model-store tests, `git grep -E "specialExams|store\.dispatch|store\.subscribe" -- src '*.test.*'`
  matches only `setupTest.js`'s seeds and `CourseExit.test.jsx`'s two
  `addModel` dispatches. Every other `store` in a test is passed to an
  `AppProvider`.
- **A store is still required in tests, by the library.** `AppProvider`
  renders a react-redux `Provider` only when given a store
  (`OptionalReduxProvider` returns bare children for `null`), and
  `Sequence.test.jsx`, `LoadedTabPage.test.jsx` and the `Unit` suites render
  the real `SequenceExamWrapper`, `OuterExamTimer` and `useExamAccess`, which
  `useSelector` the `specialExams` slice. Only `Course.test.jsx` and
  `useExamAccess.test.jsx` mock the library. The store they need is exactly
  `initializeStore()` from `src/store.ts`, which 18 suites with their own
  `AppProvider` wrapper already use.
- **Two stale `react-redux` test mocks**: `CoursewareSearchResults.test.jsx:12`
  (`jest.mock('react-redux')`, nothing under it uses react-redux) and
  `CourseTabsNavigation.test.jsx:23-26` (mocks `useDispatch` to a `mockDispatch`
  that no assertion reads). Both are left over from the `plugins` slice (#2017).
  The `generic/plugin-overrides/README.md:68` match is the *removed* line of a
  migration diff example and stays.
- `docs/decisions/0004-model-store.md` describes the deleted module. No ADR has
  been amended by any layer of #1946 (the directory's last commit is from 2021;
  `0006-thunk-and-api-naming.md` still describes thunks that no longer exist).

## Findings that shape the work

1. **There is no rendering fallout to fix.** The issue body expects to "fix
   the fallout across the suites that relied on pre-seeded models". With zero
   non-test readers the seeds are inert for every component: suites already
   resolve data through the real queries — `MountCourseQueryHooks` (14 files),
   `CourseQueryGate` (4), `seedQueryData` (13), `queryClient.fetchQuery(sequenceMetadataQuery(…))`
   (`BookmarkButton.test.jsx`). What depends on the seeds is **test-side
   reads of what the setup built**: 24 `getState().models` reads in 11 files,
   plus the ids `getTestStoreIds` derives from the model keys. By purpose:

   | Read | Sites | Fixture that carries the same value |
   |---|---|---|
   | first unit id, `Object.keys/values(models.units)[0]` | 8 — `Course.test.jsx` ×6, `test-utils.jsx` ×2 (one redundant, see 4), `LockPaywall.test.jsx:24`, `CourseOutlineTray.test.jsx:38`, `CourseOutlineTrigger.test.jsx:33`, `InstructorToolbar.test.jsx:30`, `DiscussionsSidebar.test.jsx:34`, `DiscussionsTrigger.test.jsx:34` | `unitBlocks[0].id` (`Sequence.test.jsx:32` already does this) |
   | unit / sequence / section / course titles for the Helmet title | `Course.test.jsx:93-105` | `unitBlocks[0].display_name`, `sequenceBlocks[0].display_name`, `sectionBlocks[0].display_name`, `courseMetadata.name` (the course block's `display_name` *is* `courseMetadata.name`: `buildSimpleCourseBlocks(courseId, courseMetadata.name)`) |
   | `sequences[id].gatedContent.prereqSectionName` | `SequenceContent.test.jsx:51` | `sequenceMetadata[0].gated_content.prereq_section_name` |
   | `courseHomeMeta[courseId].verifiedMode.{currencySymbol, price, upgradeUrl}` | `LockPaywall.test.jsx:40, 71` | `courseHomeMetadata.verified_mode.*` (the second case already builds its own `courseHomeMetadata`) |
   | the whole normalized `courseHomeMeta` to `seedQueryData` the metadata key | `HonorCode.test.jsx:48`, `StreakCelebrationModal.test.jsx:68` | `await getCourseHomeCourseMetadata(courseId)` through the setup's adapter — both suites install their own `MockAdapter` right after `initializeTestStore` (that is *why* they seed, per their own comments), so the fetch goes between the two lines |

2. **No request-count assertion observes the seeding requests.** Twelve
   `initializeTestStore` suites assert on `axiosMock.history`. Every one either
   installs its own `new MockAdapter(getAuthenticatedHttpClient())` after the
   setup call (which replaces the setup's adapter, so its history starts
   empty) or calls `axiosMock.reset()` / `resetHistory()` before asserting.
   The six requests the seeds made went to the setup's adapter and were never
   counted, so removing them changes no assertion.

3. **`getTestStoreIds` is exact only by construction.** Its comment says the
   factories "build a single course with a single sequence, so the ids they
   generated are the sole keys". `courseId` is the fixed
   `'course-v1:edX+DemoX+Demo_Course'` (`courseMetadataBase.factory.js:10`)
   unless the caller passes `courseMetadata`; `sequenceId` is
   `sequenceBlocks[0].id`, a Rosie sequence that differs per build. The
   fixtures `buildSimpleCourseAndSequenceMetadata(options)` returns carry both
   directly, with no store in between.

4. **`courseware/course/test-utils.jsx` calls `initializeTestStore` twice**
   and takes `courseId` from the first store, `sequenceId` / `unitId` from the
   second. The first call exists only to read ids that the second build then
   overwrites (the course id is the fixed one, so it is the same in both). The
   first call goes when the file is converted.

5. **`createTestQueryClient`'s store parameter does double duty.** It feeds
   the bridge, and it selects the app `QueryCache` whose `onError` logs.
   `courseware/data/apiHooks.test.tsx:417, 455` pass `initializeStore()` for
   the second reason only, and say so: "The app QueryCache (whose onError logs)
   still takes a store until #1977 removes the bridge." Every other suite that
   asserts on `logError` either gets the log from the hook itself
   (`bookmark/data/apiHooks.ts`, `LoadedTabPage`) or builds its own
   `new QueryClient({...})` (`course-home/data/apiHooks.test.tsx`,
   `product-tours/data/apiHooks.test.tsx`).

6. **The `excludeFetch*` options lose their meaning entirely.** They skip
   seeding and nothing else. `preventSequenceLoad` and `preventOutlineSidebarLoad`
   stay: they shape the axios mock (a never-resolving reply). The comment on
   `preventSequenceLoad` ("pair with `excludeFetchSequence`, whose seeding
   would otherwise wait on it") goes with the option.

7. **`CourseExit.test.jsx`'s pre-fetch is seeding by hand.** `fetchAndRender`
   awaits `getCourseMetadata` + `getCourseHomeCourseMetadata`, dispatches both
   with `addModel`, then `axiosMock.resetHistory()`. The results have no other
   use, and the per-URL request counts at lines 686–699 are taken after the
   reset. Both the fetch and the dispatches go; `MountCourseQueryHooks` is
   already there for the component to read through.

8. **The deletion is plugin-visible.** `@src/generic/model-store` has been an
   importable module since the first plugin README; nothing in-repo documents
   it today (`git grep -il "useModel\|model-store" -- '*.md'` returns only ADR
   0004), but an external plugin could still import `useModel`, as
   `@edx/unit-translation-selector-plugin` imported `@src/generic/plugin-store`
   until #2017. So the commit is `refactor!:`, matching #2082's convention for
   removing a plugin-reachable module.

## Decisions to settle

**D1 — `initializeTestStore` is deleted, not reshaped (findings 1, 3; settled
in discussion 2026-10-02: this is the full teardown, so the test setup stops
having a store of its own).** Today the function does three jobs: build a
store, mock the course endpoints, seed the store from them. After this layer
the third is gone and the first is `initializeStore()` to the letter, so what
is left is the second. The pieces:

- **The store comes from the app.** `render` in `setupTest.js` wraps with
  `<AppProvider store={initializeStore()}>`, a fresh store per render, the way
  it already builds a fresh `createTestQueryClient()` per render. There is
  nothing in any store that two tests could differ on (every one is an empty
  `specialExams` slice), so `render`'s `store` option, `globalStore`, the
  `overrideStore` parameter and the 29 second-store builds all go with the
  44 `{ store }` render options. The 18 suites that wrap their own
  `AppProvider store={initializeStore()}` are untouched: they already do
  this.
- **The mocks and fixtures become a synchronous helper** that calls
  `initializeMockApp()`, builds `buildSimpleCourseAndSequenceMetadata(options)`,
  installs every axios reply `initializeTestStore` installs today (including
  `preventSequenceLoad` / `preventOutlineSidebarLoad`), and **returns the
  fixtures** — `courseBlocks`, `sectionBlocks`, `sequenceBlocks`,
  `unitBlocks`, `courseMetadata`, `sequenceMetadata`, `courseHomeMetadata`,
  plus `courseId`, `sequenceId`, `unitId` picked off them (finding 3). Seeding
  was the only `await`, so the 41 call sites lose theirs; the 25 that used
  the store destructure what they need instead, and the 24 `getTestStoreIds`
  lines fold into that destructure. `getTestStoreIds`, `seedCoursewareModels`
  and `seedSequenceModels` are deleted.
- **Name: `mockCourseRequests(options)` (settled 2026-10-02).** Beside
  `logUnhandledRequests` in `setupTest.js`; says what it does. Not
  `setUpMockRequests` (the container suite's local helper, less specific
  about what is mocked) and not `buildMockCourse` (names the return, not the
  side effect callers depend on).

Rejected: keeping `initializeTestStore` and having it return the fixtures
alongside the store (a smaller diff, but it keeps a bespoke test store whose
only content is the app's own reducer, and the 29 second-store builds would
survive with nothing to distinguish them); keeping the store as a lookup
handle through a `WeakMap<store, fixtures>` (rebuilds a store-keyed side table
for data the store no longer holds).

**D2 — `createTestQueryClient()` builds the default `QueryCache` (finding 5;
settled 2026-10-02).** The store argument was the only thing selecting the
app's cache, so with it gone the helper has to pick one cache for all 65
call sites. The test for whether the app's cache belongs in tests was: does
it behave differently, should its logging be tested, is the logging useful
for diagnosing tests. None holds:

- `QueryCacheConfig` is three optional callbacks (`onError`, `onSuccess`,
  `onSettled`), fired after a query settles; no query state, data, retry or
  timing differs. The status-specific hook tests (outline 403, sequence 422,
  metadata 500) already run under the default cache.
- The cache's logging, including `logStatusAs` levels, is tested directly in
  `queryClient.test.ts` against `createAppQueryCache`. No hook's own
  `logStatusAs` meta is asserted through the helper anywhere; the only two
  helper-dependent logging assertions (`courseware/data/apiHooks.test.tsx`,
  the toggles network error and the topics config failure) assert the
  cache's generic behaviour, not the hook's.
- Diagnostic value is marginal and is noise whenever the failure is
  deliberate, which in these suites is most of the time.

So: `createTestQueryClient()` takes no parameter and no `queryCache`; the
`createAppQueryCache` import leaves `setupTest.js`; the two courseware hook
tests drop their `expect(loggingService.logError).toHaveBeenCalled()` lines
(the hooks under test log nothing themselves) and the comment that waited on
this layer. Rejected: always the app cache (production parity bought with
console noise, for behaviour no component can observe); a flag replacing the
store argument (would preserve an accidental split).

**D3 — `docs/decisions/0004-model-store.md` is left as it is (settled
2026-10-02).** The ADR log is history: no layer of #1946 has amended an ADR
(`0006-thunk-and-api-naming.md` still describes thunks that no longer exist,
`0007-testing.md` still mentions "redux tests"). The superseding ADR that
records React Query as this app's server-state layer (OEP-67 ADR-0010 is the
org-level decision) is the epic's closing work alongside #1978's dependency
removal, and is named as a task on #1978 when this layer closes it. Rejected:
prepending a one-line "Superseded" status now.

**D4 — the two stale `react-redux` mocks (verify step).** Remove both
(`CoursewareSearchResults.test.jsx:12`; `CourseTabsNavigation.test.jsx:14, 23-26`).
Neither has a reader; the issue's verify line ("`git grep react-redux src`
returns only special-exams-adjacent files") is false while they stand. The
`initializeStore` + `AppProvider` wrapper in `CourseTabsNavigation.test.jsx`
stays: the store is what `AppProvider` needs for special-exams.

**Not decisions, stated so they are not re-opened:**

- `RootState` is deleted with the `models` reducer (zero importers).
- `Register.queryMeta` becomes `{ logStatusAs?: Record<number, LogLevel> }`;
  `createAppQueryCache()` and `createQueryClient()` take no parameter;
  `index.jsx` follows.
- `package.json` keeps `redux`, `react-redux`, `@reduxjs/toolkit`: `store.ts`
  still uses `configureStore`, and `AppProvider store=` still needs a
  react-redux store for `OuterExamTimer` / `SequenceExamWrapper` /
  `useExamAccess`. That removal is #1978's library-gated step (#2018).
- The `excludeFetchCourse` / `excludeFetchSequence` options are deleted with
  their 18 call sites (finding 6). `preventSequenceLoad` and
  `preventOutlineSidebarLoad` stay.
