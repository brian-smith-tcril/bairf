Part of #1905. Depends on #2196 and #2201.

**Goal:** a learner reaching the end of a course on a frontend-base site lands on the course exit page in the state that applies, as on `master`: the celebration page with certificate status, share buttons, program completion and course recommendations; the non-passing page; or the in-progress page when scheduled content remains. They get there from the last unit's next button and by URL. The course-exit stub route from #2188 is replaced.

## What moves

Files port from the legacy `src/` tree to the same relative path under `frontend-base/src/`, with their tests, and get a line each in `frontend-base/manifest.tsv`.

- The course exit page ([`src/courseware/course/course-exit/`](https://github.com/openedx/frontend-app-learning/tree/master/src/courseware/course/course-exit)): the page component, which renders through the tab-page frame with the courseware tab active, picks the state from the certificate data, scheduled content, enrollment and passing grade, redirects to the course home when the outline request fails for a learner with access and to the course root when no state applies, and unsubscribes an audit learner from goal reminders on arrival; the celebration, non-passing and in-progress bodies; program completion; course recommendations with the catalog suggestion as fallback; the footnotes; the recommendations query and API; tracking helpers; messages. The exit-mode helper and messages already ported with #2196's unit navigation.
- The three course-exit plugin slots ([`CourseExitPluginSlots/`](https://github.com/openedx/frontend-app-learning/tree/master/src/plugin-slots/CourseExitPluginSlots)) become placeholder slots with their default content: the view-courses button, the recommendations panel, and the dashboard footnote link.
- Links and config change form per the reviewed table and the shared links module #2190 ports: the view-courses button and dashboard footnote resolve the `org.openedx.frontend.role.dashboard` role in place of the LMS `/dashboard` URL; the catalog suggestion resolves `org.openedx.frontend.role.courses` in place of `SEARCH_CATALOG_URL`; `LMS_BASE_URL` and `SITE_NAME` become the site config's `lmsBaseUrl` and `siteName`; `DISCOVERY_API_BASE_URL`, `CREDENTIALS_BASE_URL`, `SUPPORT_URL` and `SUPPORT_URL_VERIFIED_CERTIFICATE` become keys of Learning's app config under the same names. With no discovery URL configured the recommendations query returns none and the catalog suggestion shows, as on `master`.
- Pieces the page reuses that earlier issues ported: the share buttons (#2201), the request-certificate mutation and the shared links (#2190), the pricing formatter from the upgrade button, the dates and progress tab URL hooks (#2189).

## Testing

The course exit tests port with the page and reach it through the exported route array at the `course-end` path: the three states and the no-state redirect, the outline-failure redirect, the access-denied detail, the celebration page's certificate, verification, upgrade, LinkedIn and share-button cases, program completion, recommendations and the catalog fallback, the non-passing and in-progress links, the goal-reminder unsubscribe, and one request per load for each query, with mocks per the conventions #2189 set.

## Acceptance

- [ ] From the last unit, the next button reads as on `master` and lands on the course exit page; by URL the page renders the state that applies, and redirects when none does or the outline fails
- [ ] The celebration page shows certificate status, the share buttons on a course with a marketing URL, program completion when a program is complete, and recommendations or the catalog suggestion; the dashboard links and catalog link resolve their roles
- [ ] The non-passing page links to the progress tab; the in-progress page links to the dates tab; an audit learner is unsubscribed from goal reminders on arrival
- [ ] The three course-exit slots are placeholder slots rendering their default content
- [ ] Types, lint and tests of the new package pass; the legacy workflow stays green; `npm run dev` from the package serves the page in each state
- [ ] Manifest lines added for every file moved; the course-exit directory's coverage compared against the `master` baseline
