Why export-then-deprecate is right even though the old name was never importable: the README documented the old name, and the in-repo site config pattern the READMEs use (`./src` and `@src/...` imports) could import it from the old path, which this PR deletes. With the export and a `@deprecated` alias, that importer's fix is the path only, and the alias note names the new type; without the alias, the fix is path and name at once with nothing pointing from one to the other. It is the same move as frontend-base#344 decision 5 (the unversioned props interface kept as a deprecated alias of `v1`). Cost is one line. The alias goes out with a later `feat!:` under ADR 0018 section 6, no DEPR until the `stable` landing (section 8).

The export does not make #175's shape change breaking; the prop shape is contract already (ADR 0009 section 2, ADR 0018 section 2). It makes the change visible in the diff of an exported type, which is how ADR 0018 wants a maintainer to spot it; the resolution there is a new slot version, the "changing a prop's type" example in #344. That is #175's review.

Shape of the ask for this PR: export `CatalogSearchResponse`, `DataTableParams`, `TableColumn` and `TableColumnFilterChoice` from `src/index.ts` beside the `*SlotProps`, plus `/** @deprecated Renamed to CatalogSearchResponse. */ export type CourseListSearchResponse = CatalogSearchResponse;`. Home for the alias (Brian, 2026-11-06): beside the new type in `catalog-search/types.ts`, with `src/index.ts` re-exporting both. An alias in `index.ts` alone only works for a pure rename, where the old type is the new type; once a deprecated type has its own shape (as `CourseListSearchResponse` would if it kept course-only `results` after #175's union) it needs a declaration beside its replacement, so an `index.ts` alias would make the rename the one exception to that rule. Same placement as frontend-base#344, where the deprecated unversioned interface and members sit in the slot file beside `v1` and `v2`. The course name stays in the data layer marked `@deprecated` until the breaking release removes it; that is the deprecation, not a leak. The five course-about types are deferred (above).
