**Goal:** a learner who follows the unsubscribe link in a goal-reminder email lands on a frontend-base site, is unsubscribed from the reminders, and sees the result page as on `master`: the confirmation naming the course, or the error page with a contact-support link when the token is unknown. No login is needed, as on `master`. The goal unsubscribe stub route from #2188 is replaced.

## What moves

Files port from the legacy `src/` tree to the same relative path under `frontend-base/src/`, with their tests, and get a line each in `frontend-base/manifest.tsv`.

- The goal unsubscribe page ([`src/course-home/goal-unsubscribe/`](https://github.com/openedx/frontend-app-learning/tree/master/src/course-home/goal-unsubscribe)): the page, which posts the token on mount, shows the loading state, then the result page; the result page with its icon, heading, description and dashboard button; messages.
- The unsubscribe API function, into the course-home data module that #2189 established, as #2190 did for progress. It posts to `/api/course_home/unsubscribe_from_course_goal/<token>` on the LMS, an endpoint the platform leaves unauthenticated on purpose ([`outline/views.py`](https://github.com/openedx/openedx-platform/blob/master/lms/djangoapps/course_home_api/outline/views.py), `unsubscribe_from_course_goal_by_token`): the token is the credential, since the link is opened from an email on any device, and the response carries only the course title. The LMS builds the link as `<learning URL>/goal-unsubscribe/<token>` in its goal-reminder email command, so the path stays as it is.
- The route, `goal-unsubscribe/:token`, with no role (#2188) and no authentication loader: `master` initializes without requiring an authenticated user, and frontend-base's http client sends the request without a token when the visitor has no session.
- Config reads change form per the reviewed table: `CONTACT_URL` becomes a key of Learning's app config under the same name; the dashboard button resolves `org.openedx.frontend.role.dashboard` in place of `LMS_BASE_URL/dashboard`, as the other dashboard links do; the tracking call moves to frontend-base's analytics function of the same name.
- The header: on `master` the page renders Learning's header slot with the user dropdown hidden, since the visitor may be anonymous. Under frontend-base the shell renders its header on every page, in its logged-out form for an anonymous visitor, so the page renders only its main content.

## Testing

The page's tests port with it and reach the page through the exported route array at a token path: the loading state first, a known token answering with the course title and the confirmation, an unknown token answering 404 and the error page, with the request mocked per the conventions #2189 set.

The manual test needs a token. The manual-testing record carries the recipe: set a weekly learning goal with reminders on a course, read the `unsubscribe_token` of the `CourseGoal` row (or run the LMS `goal_reminder_email` command and take the link from the email), open the link in a logged-out browser, and record the result page; then open it again with a made-up token.

## Acceptance

- [ ] The page renders under the shell's header with no header of its own; the dashboard button resolves the dashboard role
- [ ] Types, lint and tests of the new package pass; the legacy workflow stays green; `npm run dev` from the package serves the page
- [ ] Manifest lines added for every file moved; the directory's coverage compared against the `master` baseline
