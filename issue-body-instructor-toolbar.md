Part of #1905. Depends on #2189.

**Goal:** the masquerade bar, the dark staff bar under the header, has on every Learning course page under frontend-base everything Learning's legacy version of it has on `master`, and appears once.

**Names:** the frontend-base shell renders the bar in its header as [`MasqueradeBar`](https://github.com/openedx/frontend-base/blob/main/shell/header/course-bar/masquerade/MasqueradeBar.tsx). Learning's legacy name for the same bar is the instructor toolbar ([`InstructorToolbar`](https://github.com/openedx/frontend-app-learning/blob/master/src/instructor-toolbar/InstructorToolbar.jsx)), and "masquerade widget" there is the "View this course as" dropdown inside it; the shell reimplements that dropdown under the same file names. The shell's bar already shows on Learning's routes once #2188 provides Learning's role under the masquerade key. So Learning does not port its legacy bar; this issue closes the one gap between the legacy bar and the shell's, moves two Learning alerts the legacy bar happened to render, and drops the one part of it that is deprecated.

**How this closes:** mostly by testing. If the shell's bar covers everything once the banners are in place, this issue closes with a comment recording what was tested and the frontend-base version it was tested against, with no pull request of its own. A pull request happens only if the Studio gate or the show condition needs a change on Learning's side.

## Same in both

The dropdown with its staff, learner, group and specific-user options; the error alert under the bar; the "View course in: Studio" button, linking to the unit container in courseware and to the course elsewhere (shell: [`StudioLink`](https://github.com/openedx/frontend-base/blob/main/shell/header/course-bar/masquerade/StudioLink.tsx), from the `cmsBaseUrl` site-config field).

## Dropped: the Insights button

The legacy bar shows "View course in: Insights" when `INSIGHTS_BASE_URL` is configured. Insights is deprecated platform-wide (openedx/public-engineering#221, with its repositories already moved to the unsupported org under openedx/public-engineering#227), and no frontend-base app carries the button. It is not replicated, and `INSIGHTS_BASE_URL` has no frontend-base equivalent. No new DEPR is needed; the existing one covers it.

## Moved: two masquerade banners

The legacy bar renders an alert list beneath it with two banners: access expiration, when staff masquerade as a learner whose course access has expired, and course start, on the progress tab while masquerading when the course has not started. Both read Learning's own course metadata and tab payloads ([`access-expiration-alert/hooks.ts`](https://github.com/openedx/frontend-app-learning/blob/master/src/alerts/access-expiration-alert/hooks.ts), [`course-start-alert/hooks.js`](https://github.com/openedx/frontend-app-learning/blob/master/src/alerts/course-start-alert/hooks.js)). They are Learning page alerts, not features of the bar, and no other app has them. Their hooks port with the tab-page frame and render through the frame's alert list on Learning's pages, under the masquerade bar, as today.

## The one gap: the Studio button gate

The legacy bar hides the Studio button unless course metadata says the user has course-author access; the shell's shows it whenever `cmsBaseUrl` is set, to any user who can masquerade. Decided in the pull request: accept the shell's behavior, or raise the gate as a frontend-base issue.

## One difference in when the bar appears

`master` shows the legacy bar when course metadata says the original user is staff. The shell shows the masquerade bar when the masquerade endpoint answers successfully and hides it on any denial ([`hooks.ts`](https://github.com/openedx/frontend-base/blob/main/shell/header/course-bar/masquerade/hooks.ts)). The pull request checks both as staff, as a course author and as a learner, and records any difference.

## Not ported

Learning's `InstructorToolbar` and its `MasqueradeWidget`; the manifest marks their files. Their tests are not ported.
