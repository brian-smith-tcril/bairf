Part of #1905. Depends on #2189.

**Goal:** course staff on a frontend-base site get what Learning's instructor toolbar gives them on `master`, once, with no second toolbar: the masquerade controls, the "View course in" Studio and Insights buttons, and the two banners shown while masquerading. The shell header already renders a masquerade bar that is a port of most of the toolbar; this issue adds the parts it lacks and retires Learning's own toolbar.

## What the toolbar is on `master`

[`InstructorToolbar`](https://github.com/openedx/frontend-app-learning/blob/master/src/instructor-toolbar/InstructorToolbar.jsx), rendered by the loaded tab page when course metadata says the original user is staff, with the Studio button gated on `hasCourseAuthorAccess`. It renders the masquerade widget, a Studio button (unit-level container link in courseware, course link elsewhere) and an Insights button when their base URLs are configured, a masquerade error alert, and an alert list on the `instructor-toolbar-alerts` topic carrying two banners while masquerading: access expiration and course start.

## What the shell already has

The shell header's [`MasqueradeBar`](https://github.com/openedx/frontend-base/blob/main/shell/header/course-bar/masquerade/MasqueradeBar.tsx) renders on routes whose roles an app provides under the masquerade key (#2188 provides Learning's root role there). It is a port of the toolbar: the same masquerade widget files, the same layout and error alert, and a [`StudioLink`](https://github.com/openedx/frontend-base/blob/main/shell/header/course-bar/masquerade/StudioLink.tsx) that builds the container link when a unit id is in the route and the course link otherwise, from the `cmsBaseUrl` site-config field. It shows itself when the masquerade endpoint answers successfully and hides on any denial or error ([`hooks.ts`](https://github.com/openedx/frontend-base/blob/main/shell/header/course-bar/masquerade/hooks.ts)).

## Gaps, and what this issue does with each

| Toolbar part | Shell bar | This issue |
|---|---|---|
| Masquerade widget, error alert | Present | Learning's copies are not ported; the shell's bar is the one control. |
| Studio button, course and unit links | Present, gated on `cmsBaseUrl` only | The course-author gate (`hasCourseAuthorAccess`) is absent: non-author staff would see the link. Decided in the pull request: accept the shell's behavior, or raise the gate as a frontend-base issue; recorded either way. |
| Insights button | Absent | Inserted into the shell's `org.openedx.frontend.slot.header.masqueradeBar.v1` slot from Learning's `slots`, rendering when the insights role resolves (an external route a site supplies; `INSIGHTS_BASE_URL` becomes that role). |
| Two masquerade banners | Absent | Their hooks port with the tab-page frame and render through the frame's alert list on Learning's pages, below the shell bar, as they render below the toolbar today. |
| Show condition | Masquerade endpoint success | `master` shows the toolbar on the staff flag in course metadata. The pull request compares the two for staff, course authors and learners and records any difference. |

## Testing

The banner hooks' tests port with their files. Learning's `slots` is asserted to contain the Insights operation with its role condition. The masquerade widget's tests are not ported; they live in frontend-base now.

- [ ] The Studio button links to the course on course-home tabs and to the unit container in courseware

- [ ] The access-expiration and course-start banners render while masquerading, as on `master`
- [ ] The course-author gate and the show condition are each either matched or recorded as a difference in the pull request
- [ ] Learning's toolbar component and masquerade widget are not in the ported tree; the manifest marks their files
- [ ] Types, lint and tests of the new package pass; the legacy workflow stays green
