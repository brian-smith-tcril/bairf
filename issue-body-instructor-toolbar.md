Part of #1905. Depends on #2189.

**Goal:** the masquerade bar, the dark staff bar under the header, has on every Learning course page under frontend-base everything Learning's legacy version of it has on `master`, and appears once.

**Names:** the frontend-base shell renders the bar in its header as [`MasqueradeBar`](https://github.com/openedx/frontend-base/blob/main/shell/header/course-bar/masquerade/MasqueradeBar.tsx). Learning's legacy name for the same bar is the instructor toolbar ([`InstructorToolbar`](https://github.com/openedx/frontend-app-learning/blob/master/src/instructor-toolbar/InstructorToolbar.jsx)), and "masquerade widget" there is the "View this course as" dropdown inside it; the shell reimplements that dropdown under the same file names. The shell's bar already shows on Learning's routes once #2188 provides Learning's role under the masquerade key. So Learning does not port its legacy bar; this issue closes the two gaps between the legacy bar and the shell's, and drops the one part of the legacy bar that is deprecated.

## Same in both

The dropdown with its staff, learner, group and specific-user options; the error alert under the bar; the "View course in: Studio" button, linking to the unit container in courseware and to the course elsewhere (shell: [`StudioLink`](https://github.com/openedx/frontend-base/blob/main/shell/header/course-bar/masquerade/StudioLink.tsx), from the `cmsBaseUrl` site-config field).

## Dropped: the Insights button

The legacy bar shows "View course in: Insights" when `INSIGHTS_BASE_URL` is configured. Insights is deprecated platform-wide (openedx/public-engineering#221, with its repositories already moved to the unsupported org under openedx/public-engineering#227), and no frontend-base app carries the button. It is not replicated, and `INSIGHTS_BASE_URL` has no frontend-base equivalent. No new DEPR is needed; the existing one covers it.

## The two gaps

1. **Two banners while masquerading.** The legacy bar renders an alert list beneath it with an access-expiration banner and a course-start banner. The shell's has neither. Their hooks port with the tab-page frame and render through the frame's alert list on Learning's pages, under the masquerade bar, as today.
2. **Studio button gate.** The legacy bar hides the Studio button unless course metadata says the user has course-author access; the shell's shows it whenever `cmsBaseUrl` is set. Decided in the pull request: accept the shell's behavior, or raise the gate as a frontend-base issue.

## One difference in when the bar appears

`master` shows the legacy bar when course metadata says the original user is staff. The shell shows the masquerade bar when the masquerade endpoint answers successfully and hides it on any denial ([`hooks.ts`](https://github.com/openedx/frontend-base/blob/main/shell/header/course-bar/masquerade/hooks.ts)). The pull request checks both as staff, as a course author and as a learner, and records any difference.

## Not ported

Learning's `InstructorToolbar` and its `MasqueradeWidget`; the manifest marks their files. Their tests are not ported.

## Acceptance

- [ ] On every Learning course route, staff see the masquerade bar once and can masquerade as a learner and as a specific user
- [ ] The Studio button links to the course on course-home tabs and to the unit container in courseware
- [ ] No Insights button; `INSIGHTS_BASE_URL` is not read anywhere in the ported tree
- [ ] The access-expiration and course-start banners render under the masquerade bar while masquerading, as on `master`
- [ ] The Studio gate and the show condition are each either matched or recorded as a difference in the pull request
- [ ] The banner hooks' tests port with their files
- [ ] Types, lint and tests of the new package pass; the legacy workflow stays green; manifest lines added
