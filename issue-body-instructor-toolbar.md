Part of #1905. Depends on #2189.

**Goal:** the dark staff bar under the header, which Learning calls the instructor toolbar, is present on every Learning course page under frontend-base with everything it has on `master`, and appears once.

**The two names:** on `master`, [`InstructorToolbar`](https://github.com/openedx/frontend-app-learning/blob/master/src/instructor-toolbar/InstructorToolbar.jsx) is the bar; the "View this course as" dropdown inside it is `MasqueradeWidget`. The frontend-base shell renders the same bar in its header as [`MasqueradeBar`](https://github.com/openedx/frontend-base/blob/main/shell/header/course-bar/masquerade/MasqueradeBar.tsx), with the same dropdown inside it (its masquerade-widget files are a port of Learning's). The shell's bar already shows on Learning's routes once #2188 provides Learning's role under the masquerade key. So Learning does not port its toolbar; this issue closes the three gaps between the toolbar and the shell's bar.

## Same in both

The dropdown with its staff, learner, group and specific-user options; the error alert under the bar; the "View course in: Studio" button, linking to the unit container in courseware and to the course elsewhere (shell: [`StudioLink`](https://github.com/openedx/frontend-base/blob/main/shell/header/course-bar/masquerade/StudioLink.tsx), from the `cmsBaseUrl` site-config field).

## The three gaps

1. **Insights button.** The toolbar shows "View course in: Insights" when `INSIGHTS_BASE_URL` is configured. The shell bar has no Insights button. This issue inserts one into the shell's `org.openedx.frontend.slot.header.masqueradeBar.v1` slot from Learning's `slots`, shown when the insights role resolves (an external route a site supplies; `INSIGHTS_BASE_URL` becomes that role).
2. **Two banners while masquerading.** The toolbar renders an alert list under the bar with an access-expiration banner and a course-start banner. The shell bar has neither. Their hooks port with the tab-page frame and render through the frame's alert list on Learning's pages, under the bar, as today.
3. **Studio button gate.** The toolbar hides the Studio button unless course metadata says the user has course-author access; the shell's shows it whenever `cmsBaseUrl` is set. Decided in the pull request: accept the shell's behavior, or raise the gate as a frontend-base issue.

## One difference in when the bar appears

`master` shows the toolbar when course metadata says the original user is staff. The shell shows its bar when the masquerade endpoint answers successfully and hides it on any denial ([`hooks.ts`](https://github.com/openedx/frontend-base/blob/main/shell/header/course-bar/masquerade/hooks.ts)). The pull request checks both as staff, as a course author and as a learner, and records any difference.

## Not ported

Learning's `InstructorToolbar` and its `MasqueradeWidget`; the manifest marks their files. Their tests are not ported; the widget's live in frontend-base now.

## Acceptance

- [ ] On every Learning course route, staff see the bar once and can masquerade as a learner and as a specific user
- [ ] The Studio button links to the course on course-home tabs and to the unit container in courseware
- [ ] The Insights button appears in the bar on Learning's routes when the insights role resolves, and not otherwise
- [ ] The access-expiration and course-start banners render under the bar while masquerading, as on `master`
- [ ] The Studio gate and the show condition are each either matched or recorded as a difference in the pull request
- [ ] Learning's `slots` is asserted to contain the Insights operation; the banner hooks' tests port with their files
- [ ] Types, lint and tests of the new package pass; the legacy workflow stays green; manifest lines added
