Part of #1905. Depends on #2192 and #2195.

**Goal:** a learner whom Learning turns away from a course, because their audit access expired, the course has not started, a prerequisite is unmet, a survey or data-sharing consent is required, or they are an enterprise learner on a course that has not started, arrives where `master` sends them; and a learner who turns out to have access lands on the course home. These are the course access redirects, the children of the `redirect/*` route. The redirect landing stub route from #2188 is replaced.

## What the route does on `master`

Nothing in openedx-platform sends a learner to `/learning/redirect/...`. The `redirect/*` route is Learning's own hop: the tab page asks the access helper ([`src/shared/access.js`](https://github.com/openedx/frontend-app-learning/blob/master/src/shared/access.js)) what to do with a denial, and for five reasons the answer is a path under `redirect/`; the course-access error page sends a learner who does have access to `redirect/home/<course id>`. Its component on `master` ([`CoursewareRedirectLandingPage.jsx`](https://github.com/openedx/frontend-app-learning/blob/master/src/courseware/CoursewareRedirectLandingPage.jsx)) shows a spinner with a screen-reader "Redirecting..." line and picks a child, each of which ([`RedirectPage.tsx`](https://github.com/openedx/frontend-app-learning/blob/master/src/courseware/RedirectPage.tsx)) calls `location.assign` during render:

| Child | Denial reason | Destination on `master` |
|---|---|---|
| `dashboard` (`?notlive=<date>` or `?access_response_error=<message>`) | course not started; audit expired; unfulfilled milestones (no query) | LMS `/dashboard` with the query, read only by the legacy dashboard template |
| `enterprise-learner-dashboard` | course not started, enterprise learner | `ENTERPRISE_LEARNER_PORTAL_URL` |
| `survey/:courseId` | survey required | LMS `/courses/<id>/survey` |
| `consent?consentPath=` | data-sharing consent required | the LMS path in the query |
| `home/:courseId` | learner has access | Learning's course home, by full page load |

## What moves

- The five children become child routes of the `redirect/*` route in the route array from #2188, each with a `loader` returning react-router's `redirect`, the mechanism frontend-base itself uses for its login redirect and the shell's home redirect. The component and its interstitial are not ported: the router redirects before anything renders, and the interstitial's visible part is a spinner that reads as loading. The two children that take a course id decode it in the loader with the helper the URL-decoding wrapper from #2195 uses, since a loader runs before the wrapper's element.
- Destinations, per the reviewed config table: `dashboard` resolves `org.openedx.frontend.role.dashboard` through `resolveRouteByRole`, so the learner reaches the installed learner dashboard app directly, or the external route the site supplies for the role, and carries no query. The `notlive` and `access_response_error` queries the access helper builds are read only by the legacy LMS dashboard template, which openedx/openedx-platform#35326 deprecates (the learner dashboard app has been the default since Quince; reopened 2026-07-31 because the removal was never done) under the umbrella openedx/openedx-platform#38921, and which frontend-app-learner-dashboard has never read in its history. The helper's two query-building lines are dead under that deprecation; the pull request removes them or records why it did not; `survey` and `consent` build their paths on the site config's `lmsBaseUrl`; `home` redirects to Learning's own course home route, a client-side navigation now that both are in one app.
- `enterprise-learner-dashboard` reads `ENTERPRISE_LEARNER_PORTAL_URL` from Learning's app config under the same name, a plain URL key, unset by default as the `.env` ships it. When it is unset the loader falls back to the `dashboard` redirect, where `master` calls `location.assign('')` and reloads into the same denial.
- The access helper and the course-access error page were ported with the tab-page frame in #2189; they build these paths unchanged.

## A note for later, not for this issue

The enterprise child exists for a denial code that openedx-platform never emits: it comes from the edx-enterprise plugin's course-start filter ([`enterprise/filters/courseware.py`](https://github.com/openedx/edx-enterprise/blob/master/enterprise/filters/courseware.py)), as does the code behind the enterprise-only access-denied page (#2192). The two are Learning's branches for that one plugin and are deprecation candidates together; that is settled outside the port.

## Testing

The component's tests port as loader tests, reaching each child through the exported route array: `dashboard` resolves the role both as a stub installed app and as an external route; `enterprise-learner-dashboard` with the key set goes to it and with the key unset falls back to the dashboard redirect; `survey` and `consent` produce the LMS URLs; `home` redirects to the course home route. Mocks follow the conventions #2189 set. The manual test triggers at least the course-not-started case on a course with a future start date and records where the learner lands, on a site with the learner dashboard app installed.
