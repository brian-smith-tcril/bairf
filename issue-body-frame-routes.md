Part of #1905. Depends on #2187.

**Goal:** Learning's route tree exists in the frontend-base package and the shell knows about it: one root route at `learning`, a child route for every URL Learning serves today, each rendering a stub page that names itself as not yet ported, roles on every route, and `provides` so the shell header's course bar lists Learning's tabs and switches between them client-side. Nothing fetches, no provider mounts, no page is ported.

**Why first:** routing and roles are the one thing every page port depends on, and they can be verified on their own. With stubs in place, a tester sees the course bar render Learning's tabs and navigate to each one, which proves the route ids, the roles and the `provides` wiring before any page carries them.

## Route tree

- One root route, path `learning`, id `org.openedx.frontend.route.learning.main`, role `org.openedx.frontend.role.learning`, element a bare outlet. Every converted app keeps the first segment of its old URL as its root route (`catalog`, `gradebook/:courseId`, `profile`, `account`); the shell concatenates app routes as written under one site basename, so this is what keeps every existing `/learning/...` link resolving.
- Child routes, one per page Learning serves today, each with its own id and role and a stub element:

  | Page | Path(s) under `learning` | Role |
  |---|---|---|
  | outline tab (course home) | `course/:courseId/home` | `org.openedx.frontend.role.courseHome` |
  | dates | `course/:courseId/dates` | `org.openedx.frontend.role.courseDates` |
  | progress | `course/:courseId/progress`, `course/:courseId/progress/:targetUserId` | `org.openedx.frontend.role.courseProgress` |
  | discussion | `course/:courseId/discussion/:path/*` | `org.openedx.frontend.role.courseDiscussion` |
  | live | `course/:courseId/live` | `org.openedx.frontend.role.courseLive` |
  | courseware | `course/:courseId`, `course/:courseId/:sequenceId`, `course/:courseId/:sequenceId/:unitId`, `preview/course/:courseId/:sequenceId`, `preview/course/:courseId/:sequenceId/:unitId` | `org.openedx.frontend.role.courseware` |
  | course exit | `course/:courseId/course-end` | `org.openedx.frontend.role.courseExit` |
  | access denied | `course/:courseId/access-denied` | `org.openedx.frontend.role.courseAccessDenied` |
  | goal unsubscribe | `goal-unsubscribe/:token` | `org.openedx.frontend.role.goalUnsubscribe` |
  | redirect landing | `redirect/*` | `org.openedx.frontend.role.learningRedirect` |
  | preferences unsubscribe | `preferences-unsubscribe/:userToken/:updatePatch?` | `org.openedx.frontend.role.preferencesUnsubscribe` |

  Route ids are `org.openedx.frontend.route.learning.<page>`; role ids follow catalog's flat camelCase. The root role on the root route is what the shell's course bar checks; the per-page roles exist so another app can resolve a specific page by role.
- A stub element renders one line: the page's name and "not yet ported". It exists so a tester can tell an unported page from a broken one; each page's port replaces it.
- No catch-all route: the shell renders its own not-found page for unmatched paths.
- Not in this issue: the URL-decoding and path-fixing wrappers around the course routes (they come with the courseware container), providers, data fetching, the header widget, slots.

## `provides`

- The root role is listed under both `providesCourseBarRolesId` and `providesCourseBarMasqueradeRolesId`, exactly as frontend-app-instructor-dashboard declares its single role. The course bar then renders on every route carrying the root role (ancestor roles count as active), and client-navigates to any tab whose URL prefix-matches a provided role's route, which `/learning` does for every tab.
- Tabs the LMS lists that no installed app provides still appear and render as full-page links; that is the shell's behavior and is not changed here.

## Testing

- Route tests render the exported route array under a memory router at each path above and assert the stub line for that page, following profile's route tests.
- No fetch is mocked because nothing fetches.
