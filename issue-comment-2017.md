## Baseline example plugin for the current `registerOverrideMethod` contract

Before changing the registry, we want a working example of how it is used today, so that (a) the contract we are about to break is written down as running code rather than inferred from `grep`, (b) the post-migration replacement can be built as a functional equivalent of something concrete, and (c) the #2017 PR has a manual test: the same example ported to the new API must behave identically.

**How the registry is used today (nothing in-repo dispatches into it):**

- The only known registrar is the published `@edx/unit-translation-selector-plugin` (npm, 0.5.0). It is a frontend-plugin-framework `DIRECT_PLUGIN` rendered in the unit title slot, so it sits inside the app's react-redux `Provider`. Inside a `useEffect` it calls `useDispatch()` and dispatches `registerOverrideMethod({ pluginName: id, methodName: 'getIFrameUrl', method })`, importing the action creator from the `@src/generic/plugin-store` alias (i.e. it compiles against learning's source via `env.config.jsx`). The `id` is the widget id from the slot config, passed in by the framework. It re-registers on every language change, relying on overwrite-by-`(pluginName, methodName)` semantics.
- The one in-repo consumer is `src/courseware/course/sequence/Unit/index.jsx`, which folds the registered overrides over its default via `usePluginsCallback('getIFrameUrl', () => getIFrameUrl({ ... }))`.
- The same package also imports `useModel` from `@src/generic/model-store`, so the model-store dissolution (#1977) breaks it independently of this issue. The two breaks should be coordinated into one plugin release.

**The example below** is a self-contained `env.config.jsx` (gitignored; drop it at the repo root and run `npm run dev`). It renders a Paragon `Card` in the unit title slot explaining what it demonstrates, and a switch that registers a `getIFrameUrl` override which sets `show_title=1` on the unit iframe URL (`getIFrameUrl` hard-codes `show_title=0`), so the LMS renders the unit title inside the iframe as well. Toggling re-registers the override, exercising the overwrite semantics. The registration is isolated in a `useIFrameUrlOverride(pluginName, transformUrl)` hook so that the before/after of the migration is a one-function diff.

```jsx
// Example plugin for the generic/plugin-store override registry (#2017). A DIRECT_PLUGIN in the
// unit title slot registers a `getIFrameUrl` override with `registerOverrideMethod`; the unit
// component folds it over its default via usePluginsCallback('getIFrameUrl').
import { useEffect, useState } from 'react';
import { useDispatch } from 'react-redux';
import { Card, Form } from '@openedx/paragon';
import { PLUGIN_OPERATIONS, DIRECT_PLUGIN } from '@openedx/frontend-plugin-framework';

import { registerOverrideMethod } from './src/generic/plugin-store';

// The registration itself: the part #2017 replaces. `pluginName` is the widget id the framework
// passes in from this config; `methodName` is the hook name the unit component folds over.
const useIFrameUrlOverride = (pluginName, transformUrl) => {
  const dispatch = useDispatch();
  useEffect(() => {
    dispatch(registerOverrideMethod({ pluginName, methodName: 'getIFrameUrl', method: transformUrl }));
  }, [transformUrl]);
};

// getIFrameUrl (Unit/urls.ts) hard-codes show_title=0; the LMS renders the unit title inside the
// xblock content when it is 1.
const withTitleShown = (iframeUrl) => {
  const url = new URL(iframeUrl);
  url.searchParams.set('show_title', '1');
  return url.toString();
};

const passThrough = (iframeUrl) => iframeUrl;

const PluginStoreExample = ({ id }) => {
  const [showTitleInIFrame, setShowTitleInIFrame] = useState(false);
  useIFrameUrlOverride(id, showTitleInIFrame ? withTitleShown : passThrough);

  return (
    <Card variant="muted" className="mb-3">
      <Card.Header
        size="sm"
        title="Plugin-store override example"
        subtitle={`Rendered as a DIRECT_PLUGIN in the unit title slot (widget id: ${id})`}
      />
      <Card.Section>
        <p className="small mb-2">
          This example plugin demonstrates the <code>generic/plugin-store</code> registry:
          it dispatches <code>registerOverrideMethod</code> for <code>getIFrameUrl</code>, and the unit
          component folds that override over its default URL via <code>usePluginsCallback</code>.
        </p>
        <p className="small mb-2">
          The override here rewrites the unit iframe URL with <code>show_title=1</code>{' '}
          (the default is <code>0</code>), so the LMS also renders the unit title inside the iframe.
          Toggling the switch re-registers the override with the new behavior.
        </p>
        <Form.Switch
          checked={showTitleInIFrame}
          onChange={(event) => setShowTitleInIFrame(event.target.checked)}
        >
          <span>Override the iframe URL with <code>show_title=1</code></span>
        </Form.Switch>
      </Card.Section>
    </Card>
  );
};

const config = {
  ...process.env,
  pluginSlots: {
    'org.openedx.frontend.learning.unit_title.v1': {
      keepDefault: true,
      plugins: [
        {
          op: PLUGIN_OPERATIONS.Insert,
          widget: {
            id: 'plugin_store_example',
            type: DIRECT_PLUGIN,
            priority: 1,
            RenderWidget: PluginStoreExample,
          },
        },
      ],
    },
  },
};

export default config;
```

**Semantics the replacement has to preserve** (all observed in the plugin above, not assumed):

1. Registration from a slot-rendered component, i.e. reachable from inside the framework's render tree.
2. Keyed by `(pluginName, methodName)`, overwrite on re-register; the latest closure wins.
3. Fold order: default first, then each registered override receives the previous result.
4. There is no unregister today; an override outlives the component that registered it. Whether the replacement adds cleanup on unmount is a behavior decision to make explicitly.
5. The consumer's default closure is re-evaluated per call, so it sees the unit component's current props.
