openedx/frontend-app-learning#2162 (filed 2026-10-06; discovery, not under #1946)

**Title:** `allowProctoringOptOut` is read from a sequence metadata field the LMS has never sent, so the "take this exam without proctoring" option is unreachable

> [!NOTE]
> This issue was authored by Claude (Claude Code) and reviewed before posting.

**What happens.** With the course advanced setting "Allow Opting Out of Proctored Exams" (`allow_proctoring_opt_out`) set to true, a learner opening a proctored exam sees the proctored entrance page with only "Continue to my proctored exam." The skip button that `@edx/frontend-lib-special-exams` renders for opt-out never appears. Observed 2026-10-06 on tutor local (library 4.1.0, LMS `edx_proctoring` path), with the setting both off and on; the setting has no effect.

**Where we read it.** `src/courseware/data/sequenceMetadata.ts` normalizes the sequence metadata response (`GET /api/courseware/sequence/{usage_key}`) and maps `sequence.allow_proctoring_opt_out` to `allowProctoringOptOut` (line 103; the type at line 81 already notes the field is "not in the payload SequenceBlock.get_metadata builds"). `Sequence.jsx` passes the normalized sequence to `SequenceExamWrapper`; the library's `ExamWrapper` stores `sequence.allowProctoringOptOut` and `EntranceProctoredExamInstructions` gates `SkipProctoredExamButton` on it. The library reads nothing else for this.

**What the LMS sends.** The endpoint returns `SequenceBlock.get_metadata()`, whose payload is built in `_get_render_metadata` (`xmodule/seq_block.py`): `is_time_limited`, `is_proctored`, `gated_content`, … and no `allow_proctoring_opt_out`. The only place the block builds that key is the `context` dict in `_time_limited_student_view`, which goes to `proctoring_service.get_student_view(...)`, the legacy courseware HTML render; it is a template context, not an API field. Nothing in edx-proctoring's serializers, views, API or models, and nothing in the course-level courseware metadata, exposes it either. Checked at `open-release/lilac.master` through `open-release/sumac.master`: the key has never been in the metadata payload.

**History.** The read was added in #485 (2021-06-14, EDUCATOR-5799, "Add 'allow_proctoring_opt_out' attribute for SequenceMetadata API"), evidently expecting a matching edx-platform change to the same API. That change never landed, so the value has been `undefined` since the read was introduced, and the library's skip flow (button → confirmation → `decline` or create-without-proctoring; unit-tested there against a seeded `true`) has never been reachable from this app.

**The library's skip request is also wrong, so option 1 alone would expose a second bug (2026-10-08).** In `@edx/frontend-lib-special-exams`, `skipProctoringExam` with no existing attempt calls `createExamAttempt(exam.id, true, false, useLegacyAttemptApi)`. That argument order predates openedx/frontend-lib-special-exams#96 (2023-04-07), which inserted `legacyAttempt` as the second parameter and only appended the new flag here; read against the current signature `(examId, legacyAttempt, startClock = true, attemptProctored = false)` it sends `start_clock: "false", attempt_proctored: <legacy flag>` to the LMS endpoint regardless of backend. edx-proctoring's create view declines a proctored exam's new attempt only when `attempt_proctored` is false (`start_clock` is then ignored), so a legacy exam gets a proctored, un-started attempt instead of a declined one; edx-exams ignores `attempt_proctored` and the request goes to the wrong service anyway. The library's tests mock the refetch and assert only the resulting status, so none of this is covered. Being fixed in the library's v5 PR (openedx/frontend-lib-special-exams#175) by restoring the pre-#96 call, with tests on the POST's URL and body per backend; the fix must ship before or with option 1.

**Options (undecided).**
1. **Add the field on the platform side.** One line in `SequenceBlock._get_render_metadata` (`'allow_proctoring_opt_out': self.allow_proctoring_opt_out`, the block already has the property) plus a courseware API test; no change here, the button starts appearing. Needs an edx-platform issue, and a decision that the MFE should offer opt-out at all.
2. **Remove the dead read.** Drop `allowProctoringOptOut` from `sequenceMetadata.ts` and stop passing it to `SequenceExamWrapper`; the library prop then defaults to false explicitly rather than by accident. The library's opt-out UI stays unreachable, which is the status quo.

Found while recording the special-exams manual baseline for #2018; not part of that work or of #1946.
