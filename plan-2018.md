# Plan: #2018 — special-exams off Redux, and off frontend-platform

Deliverable of #2018: a recommendation comment on #2018, a concrete issue on
`openedx/frontend-lib-special-exams` saying exactly what the new major does,
and a learning issue under #1946 for adopting it. Nothing is posted or filed
from this doc until told to.

Source read: `openedx/frontend-lib-special-exams` at v4.1.0 (2025-09-23).
`main` has only four build/chore commits since, so v4.1.0 is the current
source. Learning pins `^4.0.0` and has 4.1.0 installed.

## Decisions settled so far (2026-10-02)

- **Option B, not A.** Option A (a library-owned Redux store, the pre-2024
  shape of `src/data/store.js` + `withExamStore`) would leave redux,
  react-redux and the toolkit in learning's bundle transitively. The goal is
  that the frontend-base port of learning (#1905) never has redux in it, so
  the library's data layer converts to React Query. Both options are a major
  release, so A as a stopgap is work thrown away.
- **Same major also drops the `@edx/frontend-platform` peer.** A library that
  requires frontend-platform cannot be used under frontend-base, and requiring
  both bloats both. The frontend-platform surface is small once i18n is set
  aside (table below), so v5 makes the library host-agnostic: it peers on
  react, react-intl, Paragon and React Query, and the host injects config
  values, the HTTP client, a logger and the authenticated user.
- **FPF leaves the library; the one slot moves to learning.** frontend-base
  has no frontend-plugin-framework, and FPF 1.8.0 also carries react-redux
  8.1.1 as a regular dependency, so it must go for the redux goal too. The
  library exposes an override point for the submitted-timed-exam instructions;
  learning renders the existing slot ID around it with its own slot system
  (FPF on master, frontend-base's after #1905). The slot ID and its
  `timeIsOver` prop are unchanged for operators.
- **`useExamAccessToken` becomes React Query-native (D3, settled
  2026-10-02).** Both hosts of v5 (learning on frontend-platform today,
  frontend-base later) already provide a `QueryClient`, so the token is a
  query and the hook returns its state rather than a custom fetch-then-read
  pair. `useExamAccessToken()` → `{ accessToken: string, isPending: boolean }`;
  `useFetchExamAccessToken` is removed. `isPending` must be `false` when the
  query is disabled (no enclosing exam, or no `examsBaseUrl`), since React
  Query v5 reports a disabled query with no data as pending; the hook returns
  the fetching-aware flag or gates on `enabled`. Refresh policy stays
  `staleTime: 0` with the query mounted per Unit (today's refetch on every
  unit id); driving staleness from `exam_access_token_expiration` is a named
  follow-up, not part of the major.
- **One override prop, not a pattern (D5, settled 2026-10-02).**
  `SequenceExamWrapper` takes a single component prop for the submitted
  timed-exam instructions, called with `{ timeIsOver }`. No `components` map
  and no general override mechanism: the slot is the only customization point
  the library has, and its being in the library at all is the thing being
  undone, so v5 exposes the minimum that lets learning own the slot.
- **`isAuthenticated: boolean`, not the user object (D7, settled
  2026-10-04).** The library reads only the truthiness of `authenticatedUser`,
  in the early returns of `OuterExamTimer` and `ExamWrapper`; nothing under
  them, the slot included (its one prop is `timeIsOver`), ever sees the user.
  The provider prop states exactly what is used.
- **ORA is not a constraint.** `frontend-app-ora` pins `^3.4.0`, renders only
  `OuterExamTimer`, registers the reducer but never reads the slice, and is on
  React Query v4. It stays on 4.x until it chooses to take the new major.

## How it works today (v4.1.0)

**Exports** (`src/index.jsx`): `SequenceExamWrapper` (default),
`OuterExamTimer`, `useIsExam`, `useExamAccessToken`,
`useFetchExamAccessToken`, `reducer`.

**Store.** The library creates no store. Every component and the three hooks
call `useSelector(state => state.specialExams)` / `useDispatch`; the 19 thunks
read only `getState().specialExams`. The host registers `reducer` under
`specialExams` and renders the react-redux Provider (learning: `store.ts` +
`AppProvider store=`, which is frontend-platform's `OptionalReduxProvider`).

**Learning's consumers.** `Sequence.jsx` renders `SequenceExamWrapper` around
the unit content; `Unit/hooks/useExamAccess.js` calls the three hooks on every
Unit (which is inside `SequenceExamWrapper`'s children); `TabWithTimer.tsx`
renders `OuterExamTimer` on every course-home tab. Courseware and course-home
never mount both components at once.

**Slice** (`src/data/slice.js`): `isLoading`, `timeIsOver`, `activeAttempt`,
`allowProctoringOptOut`, `proctoringSettings`, `exam` (incl. `exam.attempt`
and, after `setReviewPolicy`, `exam.reviewPolicy`), `apiErrorMsg`,
`examAccessToken`. `setExamState`/`setActiveAttempt` run `appendTimerEnd`,
which stamps `timer_ends = now + time_remaining_seconds` at write time.

**Thunk shape.** Almost every writer is `updateAttemptAfter(courseId,
sequenceId, apiPromise)`: set loading, await the action, then
`fetchExamAttemptsData` and `setExamState`, clear loading. Errors go to
`setApiError`. The timer (`TimerProvider`) runs a 1s ticker that dispatches
`pollAttempt` every 60 ticks and `pingAttempt` at `pingInterval / 2`, and
emits `TIMER_*` events on an `eventemitter3` singleton that `ExamTimerBlock`
and `SubmitInstructions` listen to.

**Host coupling other than redux** (non-test files):

| frontend-platform import | Files | Used for |
|---|---|---|
| `i18n` (FormattedMessage, useIntl, defineMessages) | 43 | react-intl re-exports |
| `getConfig` | 17 | `EXAMS_BASE_URL` (24 reads), `LMS_BASE_URL` (17), `SITE_NAME` (4), `CONTACT_URL`, `PROCTORED_EXAM_RULES_URL`, `PROCTORED_EXAM_FAQ_URL` (1 each) |
| `react` (AppContext) | 2 | `authenticatedUser`, truthiness only |
| `auth` (getAuthenticatedHttpClient) | 1 | `src/data/api.js` |
| `logging` (logError) | 2 | thunks, worker handler |

Plus `PluginSlot` from `@openedx/frontend-plugin-framework` (a regular
dependency, `^1.7.0`) in `plugin-slots/SubmittedTimedExamInstructionsSlot`,
reached via `Instructions → SubmittedExamInstructions → (timed) 
SubmittedTimedExamInstructions`. Slot ID
`org.openedx.frontend.special_exams.submitted_timed_exam_instructions.v1`,
one prop `timeIsOver`, added in library PR #168, shipped in v4.1.0, listed in
docs.openedx.org's frontend plugin slots reference. No learning code
references it.

**History that matters.** Until February 2024 the library owned a
module-level store and the public API were plain functions reading it.
Library PRs #131, #133, #134 and learning PR #1284 (COSMO-173/174/175, 2U)
moved to the host-store contract so the public API could be hooks (learning's
`useExamAccess` stopped keeping its own state). Draft PR #130 is an abandoned
scratch from that series. No issue in the openedx org proposes taking the
library off Redux or off frontend-platform; #2018 is the first.

## Findings that shape the design

1. **`exam` is global and goes stale across sequences.** `ExamWrapper` fetches
   on mount only if `sequence.isTimeLimited || isLoading`; `isLoading` starts
   `true`, so the first sequence always fetches and later non-exam sequences
   do not. Navigating from an exam sequence to a non-exam one leaves the old
   `exam` in the slice, so `useIsExam()` on the non-exam Unit stays `true`.
   The timer following the learner across the course is intentional (it
   reads `activeAttempt`); the stale `exam` is not. In the new design the
   exam is keyed by sequence and the active attempt by course.
2. **Two fetches today, one slice.** `fetchExamAttemptsData(courseId,
   sequenceId)` (sequence tree) and `fetchLatestAttempt(courseId)` (outer
   timer) both write `exam` + `activeAttempt`; in edx-exams mode the first
   also calls the latest-attempt endpoint a second time. Splitting into an
   exam-for-sequence query and an active-attempt query removes the double
   fetch and finding 1.
3. **`timer_ends` is a write-time derivation.** `appendTimerEnd` uses
   `Date.now()` at `setExamState`. React Query's `dataUpdatedAt` is the same
   instant, so `timer_ends = dataUpdatedAt + time_remaining_seconds * 1000`
   in a `select` is the exact equivalent.
4. **`pollAttempt` is a read, not a write.** It fetches status and remaining
   time and patches `activeAttempt`; on `submitted`/`error` it sets
   `timeIsOver` and refetches the exam. Its 60s cadence and the "not while
   `ready_to_submit`" and "not in the grace period" guards are `enabled` and
   `refetchInterval` conditions.
5. **`checkExamEntry` and `pingAttempt` are effects, not state.**
   `checkExamEntry` races a `window.postMessage` probe against a 5s timeout
   on mount; `pingAttempt` races a worker ping on the ticker. Both end the
   exam with failure on loss. They become effects that call one
   `endExamWithFailure` mutation.
6. **`allowProctoringOptOut` is a prop.** `ExamWrapper` dispatches
   `sequence.allowProctoringOptOut` into the store; it is never written
   elsewhere. It is context from props, not state.
7. **Three pieces are genuinely client state:** `timeIsOver` (set by expire
   and by the poll), `apiErrorMsg` (set by every failure path, cleared by a
   successful poll), and the timer's `timeState`. These stay React state in
   the library's own context; nothing else in the slice does.
8. **`startProctoringSoftwareDownload` is dead.** Exported from `thunks.js`
   but not from `data/index.js`; `download-instructions/index.jsx` calls
   `softwareDownloadAttempt` from `api.js` directly (its TODO says so). Delete.
9. **`isLoading` is derived.** It is `true` while a query is pending or while
   an `updateAttemptAfter` chain runs; `isPending` of the exam query and of
   the in-flight mutation cover it. `Exam` shows the spinner on it.
10. **`expireExam` passes `activeAttempt.course_id` where every sibling passes
    `exam.course_id`** (the thunk's own comment: "this sure looks like a
    bug"). A faithful port keeps it; flag in the library issue, don't fix
    silently.
11. **Only truthiness of `authenticatedUser` is read.** `OuterExamTimer` and
    `ExamWrapper` return early when it is falsy.
11a. **`ExamTimerBlock` leaks its `TIMER_LIMIT_REACHED` listener** (found
    writing the #2163 baseline tests, 2026-10-07). It registers
    `Emitter.once(TIMER_LIMIT_REACHED, () => dispatch(expireExam()))` on the
    module-level `eventemitter3` singleton, and its cleanup calls
    `Emitter.off(TIMER_LIMIT_REACHED, () => dispatch(expireExam()))` with a
    *new* arrow, which removes nothing. Every timer mount in a session adds a
    listener; when the limit is reached each one dispatches `expireExam`, so
    a learner who mounted the timer N times (tab navigation with the outer
    timer, re-entering the exam) gets N `submit` PUTs. In Jest the leaked
    listeners are bound to earlier tests' stores, so the time-out test sees
    one submit per earlier timer mount in its file (one when run alone); it
    asserts "every action is a submit, at least one" and names the cause.
    Pre-existing; the fix is the library's (v5 drops or rewires the emitter);
    not filed yet.
12. **The library's tests build a store per test** (`initializeTestStore` in
    `src/setupTest.js`, Rosie factories, `axios-mock-adapter`). The factories
    and the HTTP mocking carry over; the store builder becomes a
    `QueryClient` + provider wrapper.

## v5 design

### Peers and dependencies

- **peerDependencies:** `react`, `react-dom`, `react-intl`,
  `@openedx/paragon`, `@tanstack/react-query` (^5). Removed:
  `@edx/frontend-platform`, `react-redux`, `redux`, `@reduxjs/toolkit`.
- **dependencies:** `eventemitter3` stays (timer events; replacing it is a
  separate cleanup). `@openedx/frontend-plugin-framework` removed. Fontawesome
  and `babel-polyfill` untouched here.
- i18n imports switch from `@edx/frontend-platform/i18n` to `react-intl`
  (same symbols). The host's `IntlProvider` serves them under either host.
  The translation pipeline (atlas) is unchanged.

### Host services: `SpecialExamsProvider`

One provider the host mounts once, above both components and above every
place it calls the hooks. The host also supplies the `QueryClientProvider`
(learning has one; frontend-base's shell has one); the library uses the
host's client so its errors flow through the host's `QueryCache` logging and
its keys are visible in the host's devtools. Keys are namespaced
`['specialExams', …]`.

```tsx
<SpecialExamsProvider
  config={{ examsBaseUrl, lmsBaseUrl, siteName, contactUrl, proctoredExamRulesUrl, proctoredExamFaqUrl }}
  httpClient={getAuthenticatedHttpClient()}   // axios instance
  logError={logError}
  isAuthenticated={!!authenticatedUser}
>
```

`src/data/api.js` takes `config` and `httpClient` as arguments from the
hooks, which read them from the provider's context. (An earlier draft had a
module-level `setServices` for the thunks; with the data layer converted
before the provider arrives, no non-hook code calls `api.js`, so there is no
registry. 2026-10-07; see `plan-175.md` commit order.)

### Exam identity: `SequenceExamWrapper` provides it

`SequenceExamWrapper` puts `{ courseId, sequenceId, allowProctoringOptOut }`
and the two client-state values (`timeIsOver`, `apiError`, with setters) into
an internal context for its subtree. The public hooks read that context, so
`useIsExam()` outside any wrapper is `false` and inside one is "this
sequence's exam exists" (fixes finding 1). `OuterExamTimer` renders no such
context; it reads only the active-attempt query.

### Queries (6)

| Query | Key | Fetch | Enabled | Replaces |
|---|---|---|---|---|
| exam for sequence | `['specialExams','exam', courseId, sequenceId]` | `fetchExamAttemptsData(...).exam` | `sequence.isTimeLimited` | `getExamAttemptsData`, `setExamState.exam` |
| active attempt | `['specialExams','activeAttempt', courseId]` | `fetchLatestAttempt(...).active_attempt`, `select` adds `timer_ends` from `dataUpdatedAt` (finding 3) | authenticated | `getLatestAttemptData`, `setActiveAttempt`, `appendTimerEnd` |
| poll | `['specialExams','poll', attemptId]` | `pollExamAttempt(pollUrl, sequenceId)` | attempt started, status ≠ `ready_to_submit`, seconds left ≥ 0; `refetchInterval: 60_000` | `pollAttempt` |
| proctoring settings | `['specialExams','proctoringSettings', courseId, examId]` | `fetchProctoringSettings` | exam type ∈ onboarding/practice/proctored and `examId` | `getProctoringSettings`, `setProctoringSettings`; default object becomes `placeholderData` |
| review policy | `['specialExams','reviewPolicy', examId]` | `fetchExamReviewPolicy(...).review_policy` | mounted in `ReadyToStartProctoredExamInstructions` | `getExamReviewPolicy`, `setReviewPolicy` |
| access token | `['specialExams','accessToken', examId]` | `fetchExamAccessToken` | `examId && config.examsBaseUrl` | `examRequiresAccessToken`, `setExamAccessToken` |

On poll data: patch the active-attempt cache (`time_remaining_seconds`,
`attempt_status`) with `setQueryData`; if `submitted`/`error`, set
`timeIsOver` and invalidate the exam query (today's `pollAttempt` tail).

Access token refresh: learning's `useExamAccess` re-runs the fetch on every
Unit id change today. `staleTime: 0` with the query mounted per Unit keeps
that; `exam_access_token_expiration` driving `staleTime` is a follow-up (D3, settled).

### Mutations (10) and effects (2)

Every attempt action is `useMutation` whose `onSuccess` invalidates the
exam-for-sequence and active-attempt queries (today's `updateAttemptAfter`
refetch) and whose `onError` sets `apiError` (today's `handleAPIError`).

| `submitExam` | mutation → `submitAttempt` + worker submit message; same other-exam redirect branch | |

### Timer

`TimerProvider` keeps its 1s ticker and `timeState`; it reads the active
attempt and `exam.time_limit_mins` from the queries, calls the ping effect,
and emits the `TIMER_*` events as today. Polling leaves the ticker (it is the
poll query's `refetchInterval`). `ExamTimerBlock` and `SubmitInstructions`
keep their emitter subscriptions.

### Slot → override point

`SubmittedTimedExamInstructionsSlot` and the FPF dependency are deleted.
`SequenceExamWrapper` gains a component prop for the submitted-timed-exam
instructions, called with `{ timeIsOver }`, defaulting to today's `<h3>`
(both messages). The README and screenshots move to learning (below).

### Tooling (added 2026-10-07)

`@openedx/frontend-build` is a devDependency of the library with no bearing
on consumers, but frontend-base lists it among the libraries it supersedes
and everything it supplies a library can declare directly. v5 replaces it
with `tsc` (CommonJS `dist/`, `target: ES6` per frontend-base ADR 0005,
declarations shipped), `eslint` with `@edx/eslint-config`, `jest` with
`babel-jest`, `@formatjs/cli`. New library code is TypeScript. Details and
decisions in `plan-175.md` commit 0a.

### Consumer-facing backend mock (added 2026-10-07)

v5 ships a backend mock for consumers as `@edx/frontend-lib-special-exams/testing`
(TypeScript, plain builders, no `rosie` at runtime), built from the same payload shapes
its own tests use: both URL families, the attempt state machine (create,
the `action` transitions, poll countdown), settings, review policy and
access token, with failure switches. Learning's `src/tests/mockSpecialExams.ts`
(#2163) is its first consumer and is replaced by it in the learning swap
layer, so the knowledge of what the exam backend looks like lives in the
library that talks to it and changes in the same PR as the client code.

### Tests (library)

`initializeTestStore` → a `QueryClient` per test and a `render` wrapper of
`QueryClientProvider` + `SpecialExamsProvider` (with a mock `httpClient` the
existing `axios-mock-adapter` setup attaches to) + `IntlProvider`. Rosie
factories carry over as query payloads. Thunk tests (`data/redux.test.jsx`)
become hook tests with `renderHook`.

### Exam test adaptations found by running `Sequence.specialExams.test.tsx` against the v5 queries (2026-10-09)

Checked from the library source (commit 3 of #175) with `useExamAccess`
replaced by the swap layer's `{ blockAccess: isExam && isPending }`. 79 of
79 pass with these five changes, which belong to the swap layer:

1. **"on a sequence that is not an exam › asks for the exam once"** →
   "asks for the latest attempt once and never for the exam": zero exam
   requests, one `/exams/attempt/latest` (lib decision 5: a non-exam
   sequence mounts the attempt query, not the exam query). Add a
   `latestAttemptRequests()` helper beside `examRequests()`.
2. **"when the running attempt belongs to a different sequence"** (both
   cases): the non-exam sequence shows its unit at once and the in-course
   timer arrives when the attempt query lands, so the `beforeEach` waits
   `await screen.findByRole('button', { name: 'End My Exam' })` before
   clicking it instead of `getByRole` right after the unit frame.
3. **"as staff masquerading as a learner with no attempt › shows the unit
   behind it"** → `await findUnitFrame()`. v4's `useExamAccess` set
   `blockAccess` from `useState(isExam)` at mount, when the exam had not
   loaded, so it never blocked in this test; the swap layer's hook blocks
   while the token query is pending, so the unit follows the token by one
   fetch.
4. **"when ready to start on an LTI exam › with the proctoring app replying
   from the exams origin"**: the `beforeEach` advanced fake timers 6 s
   right after the instructions appeared; the probe now leaves in the same
   React commit as those instructions (lib decision 3.6), and jsdom
   delivers `postMessage` on a *real* zero timer, so the fake 5 s timeout
   could fire first and end the attempt with an error PUT (3 of 3 runs in
   isolation, 1 of 3 in the full file). Record that the probe was answered
   in the `reply` listener and `await waitFor(() => expect(replied).toBe(true))`
   before advancing.
5. **The fake-timer hazard (`with no proctoring app answering`)**: after
   that block, every later React state update in the file was dropped
   (four unrelated tests failed only when run after it). Mechanism:
   frontend-build's Jest `setupFiles` requires `babel-polyfill` (core-js
   2.6.12), whose `setImmediate` polyfill defers through the global
   `process.nextTick`; React's scheduler (0.23.2) captures that
   `setImmediate` at load as its host callback and tracks it with an
   `isMessageLoopRunning` flag; Jest's modern fake timers fake `nextTick`,
   and `jest.useRealTimers()` discards whatever is still pending on the fake
   clock. The block's last React Query refetch resolved after the test's
   final `advanceTimersByTime`, the scheduler's host callback landed on the
   fake clock, `useRealTimers()` dropped it, and the scheduler waited
   forever for a callback that never came. Fix in that block's `afterEach`:
   `await act(async () => { await jest.runOnlyPendingTimersAsync(); })`
   before `jest.useRealTimers()`. This is a test-environment hazard for
   any fake-timer test in learning whose last React work lands on the fake
   clock, not a library behaviour; the Redux version happened to finish
   its work before the clock swap.

### Settled: an exam unit waits for its fresh access token (raised and settled 2026-10-09)

Found while building layer 2. `Unit` is keyed by unit id, so each unit mounts
its own token query and refetches (`staleTime: 0`, D3): the request count
per unit matches v4. What differs is whether the unit waits for it. v4's
`useExamAccess` started `blockAccess` as `useState(isExam)` on each mount and
cleared it in the fetch's `.finally`, so every exam unit stayed hidden until
its own fetch finished, then rendered once with the fresh token. In v5,
`useExamAccessToken()` returns `isPending: query.isLoading`, which is false
whenever the cache already holds a token. On the second exam unit the iframe
therefore renders at once with the previous unit's token, and when the fresh
token arrives the `exam_access` parameter changes and the iframe reloads (a
second load, possibly first with an expired token, which edx-exams' check in
`render_xblock` would refuse).

Options were (a) the library reports pending until the mounted query's
fetch settles, restoring v4's behaviour, or (b) accept the render-then-reload.
**(a) chosen**: `useExamAccessToken()` returns `isPending: query.isFetching`,
and the token query also stops refetching on reconnect (it already did not on
focus), since `isFetching` would otherwise hide a unit mid-exam on any
background refetch. Retries stay the host `QueryClient`'s (learning's: up
to three for 5xx and network errors, none for 4xx), so during an outage a
unit is hidden about 7 s longer than v4's single attempt before rendering
with the same token v4 would have used; `retry: false` was not taken.
Amended into lib commit 3 of #176 (lib decision 3.7);
learning's `useExamAccess` is unchanged and takes it through the re-packed
tarball.

## Working across the two repos (verified 2026-10-06)

**Local checkout → learning dev server.** frontend-build 14.6.16 reads a
gitignored `module.config.js` at learning's root (`getLocalAliases.js`) and
aliases the named package to a local directory, resolving that package's
*peer* dependencies back into learning's `node_modules` so there is one React,
one react-redux, one frontend-platform. The library is checked out as a
sibling, `../frontend-lib-special-exams` (fork `brian-smith-tcril`, `main`;
no `upstream` remote yet). Recipe:

```js
// frontend-app-learning/module.config.js (gitignored)
module.exports = {
  localModules: [
    { moduleName: '@edx/frontend-lib-special-exams', dir: '../frontend-lib-special-exams', dist: 'src' },
  ],
};
```

- `npm ci` in the library first: its own runtime dependencies
  (`eventemitter3`, FPF today) resolve from *its* `node_modules`, and without
  them the compile fails with two module-not-found errors (observed).
- `dist: 'src'` points at the library's JSX source; learning's babel rule
  (`exclude: /node_modules\/(?!@(open)?edx)/`) compiles it because the alias
  path is outside `node_modules`. No `npm run build` in the library per change.
  Observed: `webpack.dev.config.js` compiled successfully with every library
  module coming from `frontend-lib-special-exams/src/…` and a single
  `react-redux` in the bundle.
- **Webpack dev only, out of the box.** The alias is applied in
  `webpack.dev.config.js` and `webpack.dev-stage.config.js`; `npm run build`
  and Jest keep using the installed package.
- **Jest, local and uncommitted (verified 2026-10-07).** A block at the end
  of `jest.config.js` mirrors `getLocalAliases` for Jest: when the gitignored
  `module.config.js` exists, each local module is mapped by anchored
  `moduleNameMapper` entries to its directory (`^name$` and `^name/(.*)$`),
  every peer dependency named in that module's `package.json` is mapped back
  to learning's `node_modules` (one React), and any pre-existing mapper for the
  module (the repo's unanchored special-exams entry) is removed. Pointed at
  the library's `src`, there is no build step: the sibling path is outside
  `node_modules`, so ts-jest transforms its JSX as it does learning's own
  `.jsx`. Observed: the 97 exam tests pass against the sibling's `src`; a
  message edited there fails the three tests that look for it; reverted. The
  block is not committed: it is the dev loop for the library work, and the
  layer that lands installs the vendored tarball, so the committed Jest
  config keeps resolving the installed package. The principled home for this
  is frontend-build's `createConfig('jest')`; not filed.

**Demonstrating a library PR with a learning branch.** Facts: the library's
`dist/` is gitignored and built only by `prepublishOnly` (`make build`,
babel, ~1 s), so installing from a git branch yields no `dist`; `npm pack`
after `npm run build` produces `edx-frontend-lib-special-exams-<version>.tgz`,
206 kB packed / 855 kB unpacked / 164 files, and it ships
`dist/data/__factories__/` (the Rosie factories), importable from learning's
tests as fixtures. The repo's `package.json` version is `1.14.0`;
semantic-release sets the real version at publish, so a locally packed
tarball carries that stale number (harmless for a `file:` dependency).
Semantic-release runs on `main` only, with no prerelease channel.

Options, cheapest first:

1. **Tarball committed on a learning testing branch** (recommended).
   `npm run build && npm pack` in the library; copy the `.tgz` into learning
   (e.g. `vendor/`), `npm install ./vendor/<file>.tgz` so `package.json` reads
   `"@edx/frontend-lib-special-exams": "file:vendor/<file>.tgz"` and the lock
   records its integrity; push the branch, open a *draft* learning PR for CI
   and the deploy preview, and link it from the library PR. Exact bytes under
   review, `npm ci` works offline, no change to the library's packaging. One
   commit per iteration. The branch never merges; the real adoption PR swaps
   `file:` for `^5.0.0` once v5 is published.
2. **Fork branch of the library with `dist` force-added**
   (`git add -f dist`), learning depends on
   `github:brian-smith-tcril/frontend-lib-special-exams#<sha>`; npm's GitHub
   tarball honours `files: ["dist/"]`, so the committed `dist` installs.
   Equivalent to 1 with the blob on the fork instead of in learning; two
   commits per iteration (rebuild + lock bump).
3. **A `prepare` script in the library** (`"prepare": "npm run build"`): npm
   runs `prepare` for git dependencies, installing the library's devDependencies
   and building `dist` during learning's `npm ci`, so a plain
   `github:openedx/frontend-lib-special-exams#<branch>` works with nothing
   committed. A legitimate library improvement for v5, at the cost of a slower
   consumer install and `prepare` running on every local `npm install` in the
   library. Not needed for the first demo.
4. **npm prerelease channel** (semantic-release `branches` with a prerelease
   entry, workflow trigger widened): cleanest for consumers, needs maintainer
   agreement and the repo's npm token; defer unless v5 drags on.
