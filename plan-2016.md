# Plan: #2016 — Convert getCourseDiscussionTopics to React Query

## Context

Part of epic #1946 (Redux → React Query, Stage 1) and the #1976 courseware
decomposition — **Target 5 (leaf)**. `getCourseDiscussionTopics` is the **last
thunk in `src/courseware/data/thunks.js`** (#2015 removed the other two), so
this conversion deletes the file and removes the final `dispatch`-based fetch
from the courseware subtree.

### How it works today

The thunk (`courseware/data/thunks.js`) does two sequential API calls:
`getCourseDiscussionConfig(courseId)` (raw, un-camelCased response), and —
only when `config.provider === 'openedx'` ("the legacy provider uses the
xblock") — `getCourseTopics(courseId)`, dispatching
`updateModels({ modelType: 'discussionTopics', models: topics.filter(t => t.usageKey), idField: 'usageKey' })`.
Everything is wrapped in try/catch → `logError`. Note the model store keys
these models by **`usageKey`** (the unit id), while each topic keeps its own
`id` field (the discussion topic id) — readers check both.

Sole dispatcher: the widget-registry prefetch path. `SidebarContextProvider.jsx:93-99`
runs a post-mount effect calling `widget.prefetch({ courseId, course, dispatch })`
for every enabled widget; the discussions widget's `discussionsPrefetch`
(`widgets/discussions/widgetConfig.js`) gates on `DISCUSSIONS_MFE_BASE_URL`
being configured and the course having a `discussion` tab, then dispatches the
thunk. **The prefetch signature `({ courseId, course, dispatch })` is a
documented plugin contract** (`sidebar/README.md:25,53-66`,
`ARCHITECTURE.md:166-179`) — external widgets registered via the
`SIDEBAR_WIDGETS` config key can supply their own `prefetch` and may rely on
receiving `dispatch`.

Readers (all `useModel('discussionTopics', unitId)`; none convert here —
useModel→query-result read conversions are #1977's home):
- `SidebarContextProvider.jsx:35` — feeds `unit` into `discussionsIsAvailable`.
- `DiscussionsSidebar.jsx:22` / `DiscussionsTrigger.jsx:21` — render gate
  (`topic?.id && topic?.enabledInContext`).

## 1. `courseware/data/apiHooks.ts` — a prefetch function, not a hook

No reader converts in this issue, so nothing needs `useQuery`; the one
consumer is imperative (an effect-driven prefetch). Export a plain function:

```ts
export const prefetchDiscussionTopics = (queryClient: QueryClient, courseId: string) => (
  queryClient.prefetchQuery({
    queryKey: coursewareQueryKeys.discussionTopics(courseId),
    queryFn: async () => {
      const config = await getCourseDiscussionConfig(courseId);
      // Only load topics for the openedx provider, the legacy provider uses
      // the xblock
      if (config.provider !== 'openedx') {
        return [];
      }
      const topics = await getCourseTopics(courseId);
      return topics.filter(topic => topic.usageKey);
    },
    meta: { models: [{ modelType: 'discussionTopics', strategy: 'updateModels', idField: 'usageKey' }] },
  })
);
```

- The provider gate moves inside `queryFn` (invisible to callers, exactly the
  thunk's structure); the original comment moves with it. Non-openedx returns
  `[]` — the bridge's `updateModels` over an empty array is a no-op, matching
  the thunk's dispatch-nothing path (`models.discussionTopics` stays unset
  either way).
- `prefetchQuery` never rejects; failures log through the app QueryCache
  `onError` → `logError`, the thunk's catch behavior.
- `coursewareQueryKeys.discussionTopics(courseId)` joins `queryKeys.ts`.
- (`getCourseDiscussionConfig` needs a `provider` type — either a small return
  type on the api function or a local structural type; no `as any`.)

## 2. `data/modelStoreBridge.ts` — `idField` pass-through

The `discussionTopics` model is keyed by `usageKey`, which `ModelMirror`
can't express today. Add optional `idField?: string` to `ModelMirror` and
forward it in the dispatched action payloads — the model-store slice already
accepts `idField` on every add/update action (`slice.js`), so the bridge is
the only gap.

## 3. Prefetch contract: replace `dispatch` with `queryClient` (BREAKING)

- `SidebarContextProvider.jsx`: `const queryClient = useQueryClient();` and the
  effect becomes
  `widget.prefetch({ courseId, course: courseMetaRef.current, queryClient })`
  (deps swap `dispatch` for the stable `queryClient`). **`dispatch` leaves the
  contract now, not at teardown**: it's a documented surface for external
  `SIDEBAR_WIDGETS`, but the mechanism is ~5 months old (PRs #1885/#1897),
  a code search finds no consumer, its only in-repo user was this thunk, and
  Redux removal (#1976) makes the break inevitable — breaking here means one
  contract change instead of two, with the whole thunk-dispatch →
  query-prefetch story in one PR. `useDispatch` and the `react-redux` import
  leave the provider entirely. The commit advertises the break twice: a
  `refactor!:` subject and a `BREAKING CHANGE:` footer (semantic-release
  major) naming the contract change.
- `widgets/discussions/widgetConfig.js`: `discussionsPrefetch` takes
  `({ courseId, course, queryClient })` and calls
  `prefetchDiscussionTopics(queryClient, courseId)`; the
  `baseUrl && edxProvider` gate is unchanged. Import of the thunk dies.

## Behavior changes

- **Retries**: the thunk fetched once; the query gets the app default
  `shouldRetryQuery` (up to 3 retries on 5xx/network). Same delta every
  converted query has taken.
- **Deduplication/staleness**: `prefetchQuery` dedupes an in-flight fetch and
  respects staleness (default `staleTime: 0`, so effect re-fires still
  refetch) — effectively the thunk's fire-every-effect behavior.
- Otherwise faithful: same two-call sequence, same provider gate, same
  `usageKey` filter and model keying, same `logError`-and-swallow.

## Decision doc

For the PR body at submit time:
- Prefetch function, not a hook — the only consumer is imperative; readers
  stay on `useModel` via the bridge (read conversions are #1977).
- Provider gate lives inside `queryFn`; non-openedx resolves to `[]` (bridge
  no-op ≙ thunk's dispatch-nothing).
- Bridge gains `idField` pass-through (`discussionTopics` is usageKey-keyed;
  slice already supported it).
- Widget prefetch contract *broken deliberately*: `dispatch` → `queryClient`.
  Documented surface, but ~5 months old with no findable consumer, and the
  Redux teardown (#1976) makes the break inevitable — one contract change now
  instead of two; `BREAKING CHANGE:` footer on the commit; docs updated in the
  same layer. `useDispatch` leaves `SidebarContextProvider`.
- `courseware/data/thunks.js` deleted — last thunk gone.
- Tests seed through the real prefetch + bridged test client instead of
  `executeThunk`.
- Retry/dedup deltas per the standard query-conversion posture.
